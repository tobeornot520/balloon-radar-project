# 气象与场地方向：阻塞事项和补充采集方案

版本：V1.0  
日期：2026-09-25  
用途：导师沟通、外场准备和环境因素验证的统一工作文件

## 1. 先说结论

当前项目还没有完成一轮“按本项目问题设计”的气象与场地实验。最近入库的 RSTM 数据是学姐既有实验数据，只能用于格式学习、读取器开发和探索性预研，不能替代本项目的正式采集。

环境方向目前的主要问题不是“缺一个更复杂的网络”，而是缺少能把雷达信号、气象、场地、目标状态和真值对应起来的实验记录。没有这些记录，模型即使出现分数变化，也无法判断变化来自天气、场地、目标、日期还是设备配置。

本文件把任务拆成两条门：

```text
事实门：设备、时间、标定、标签和场景记录能否被证明？
影响门：在同条件目标/背景对照下，天气或场地是否真的改变了指标？
```

事实门没有通过时，不做正式环境增益结论；影响门没有通过时，只报告分层现象，不写“气象因素导致了性能变化”。

项目总状态因此仍是：主 UAV 检测前端有冻结的开发证据；气象/场地影响验证和本项目空飘球实验仍处于外部事实准备阶段。

## 3. 补充采集的总体原则

### 3.1 先采“能证明链路”的数据，再采“能比较因素”的数据

不能一开始就把风、雨、建筑、目标种类全部混在一起。建议按以下顺序推进：

1. **E0 能力与同步**：确认雷达、视频、气象仪、真值记录和写盘链路；
2. **E1 Pilot**：同一场地、同一配置、目标和背景配对，先验证标签和质量；
3. **E2 单因素扩展**：固定目标和雷达配置，分别改变天气或场地；
4. **E3 组合条件**：在已有单因素证据后再采风+场地组合；
5. **E4 锁定评价**：新日期或新场地，冻结模型后只评价一次。

### 3.2 环境因素先做“条件变量”，不急着做天气分类

第一阶段不设置“晴/雨/大风”分类头作为项目目标。天气和场地先用于：

- 按条件分组报告 `Pfa`、`Pd`、`Joint Pd` 和定位误差；
- 检查模型是否利用日期、场地或气象条件的捷径；
- 作为轻量校准或分数修正的输入；
- 判断哪些变量值得进入正式多域模型。

只有当样本量、同步质量和条件覆盖足够时，才讨论天气识别或联合任务。

## 4. 必须采集的数据

### 4.1 雷达和计算链

每个 session 必须保留：

- 原始 H/V IQ 或明确记录不能提供 H/V 的原因；
- 雷达型号、固件/软件版本、中心频率或频段、PRF、带宽、脉冲宽度、每帧脉冲数、采样率和距离门；
- 文件、帧、波束、扫描、脉冲之间的关系；
- `radar_config_id`、配置导出文件、预处理说明和哈希；
- 原始流速、持续写盘速率、磁盘余量、丢帧、溢出和异常日志；
- 推理设备、模型版本、队列长度、延迟和资源记录（进入实时性实验时）。

### 4.2 时间和同步

- 每个帧或脉冲的 UTC 时间和硬件序号；
- `scan_id`、扫描内序号、时钟来源、分辨率和重置计数；
- 雷达、视频、真值记录和气象设备的时钟映射；
- 每个 session 至少一个可见同步事件，Pilot 总计至少五个；
- 事件的同步误差、接受/拒绝原因；
- 丢帧、缓存溢出和重启后的上下文处理记录。

文件名时间、文件系统 mtime 和推断出来的波束顺序不能升级为真实采集顺序。

### 4.3 目标、背景和真值

每个目标事件必须有：

- `target_present`、目标类别、对象编号和状态起止时间；
- 球体规格、载荷类别/质量/安装、绳长和悬挂方式；
- 稳定、摆动、旋转、上升/下降等运动状态；
- 距离、方位/俯仰、速度真值及测量方法和不确定度；
- 视频覆盖、操作记录、目标出现/消失口令和轨迹文件。

每个目标 session 必须有可比的背景 session：同日期、同场地、同配置、同标定，尽量相近时间。背景不能只是在另一个日期采集的“空场”。

### 4.4 气象变量

最低字段：

| 类别 | 字段 | 单位/记录方式 | 说明 |
|---|---|---|---|
| 风 | `wind_speed_mean`、`wind_speed_gust` | m/s，固定采样间隔 | 区分平均风和阵风 |
| 风向 | `wind_direction_deg` | 0--360 度 | 必须记录传感器朝向和真北定义 |
| 派生风 | `wind_u`、`wind_v` | m/s | 由风速和风向转换，固定坐标约定 |
| 温湿压 | 温度、相对湿度、气压 | 摄氏度、%、hPa | 记录传感器高度和校准 |
| 降水 | 降水率、累计量、降水类型 | mm/h、mm、类别 | 无降水设备时填 `unknown`，不填 0 |
| 能见度 | 能见度或可替代观测 | m | 记录测量方法；不能用肉眼等级替代数值 |
| 质量 | 传感器状态、缺失、异常 | 质量标记 | 保留原始值和质量码 |

如果没有垂直风廓线设备，只能研究近地面风况与雷达指标的关系，不能称为完整风场建模。

### 4.5 场地变量

#### 固定场景档案

- `site_id`、雷达经纬度/高度和朝向；
- 雷达视线内的建筑、树木、地面、金属设施、水面和其他强反射体；
- 各方位遮挡角、可见天空比例和近距离遮挡区；
- 现场照片、平面示意、设备布置和测量日期；
- 可用的 DEM/DSM/遥感资料及分辨率、来源和版本。

#### 从背景 IQ/RD 计算的经验场地特征

- 距离-方位背景功率分位数；
- 背景峰占用率、峰稳定性和近零多普勒能量比例；
- 背景分布的时间变化、异常峰数量和空场噪声底；
- 目标所在方向的背景风险值；
- 场地档案与实测背景图之间的配准版本。

经验背景图是站点先验，不是物理地形真值；地图模型和实测背景必须分别保存。

## 5. 分阶段采集矩阵

### E0：能力与干运行

| 项目 | 最低要求 |
|---|---|
| 连续写盘 | 固定配置连续原始 IQ 不少于 300 s，无未解释中断 |
| 纯背景 | 不少于 600 s，覆盖启动、稳定、停止 |
| 同步 | 雷达、视频、气象和真值至少 5 个可见事件 |
| 标定 | 通道映射、参考目标、空场和 `calibration_id` |
| 备份 | 离场前至少两份独立存储和 SHA-256 |
| 质量 | 文件大小、首尾序号、丢帧、饱和、时钟重置均有记录 |

E0 只允许检查链路，不能产生模型性能结论。

### E1：最小 Pilot

每个 session 连续 120--300 s，全程视频和环境记录：

| 场景 | 独立 session | 目的 |
|---|---:|---|
| 纯背景 | 3 | 建立背景波动和虚警基线 |
| 无载球体 | 3 | 建立目标参考 |
| 同一球体有载且稳定 | 3 | 初步观察载荷影响 |
| 同一球体有载且自然摆动/运动 | 3 | 检查状态标注和时域接口 |

Pilot 必须有同日期、同场地、同配置背景；不通过时重做 Pilot，不直接进入正式训练。

### E2：环境因素扩展

建议采用“单因素优先”的三条线：

1. **天气线**：固定场地、目标、雷达配置，覆盖实际可安全获得的低风/有风/阵风，降水和能见度按现场条件记录；
2. **场地线**：固定目标、配置和尽量相近天气，比较开阔地、建筑/金属设施附近、树木/复杂背景；
3. **对象线**：固定天气和场地，比较无载/有载/不同运动状态。

每条线都必须有目标和背景配对，不要求一次完成全部组合。没有安全条件时，不为追求降水样本强行外场作业。

### E3：锁定评价

- 至少一个新日期，条件允许再增加新场地；
- 目标和背景同时出现；
- 模型、特征、阈值、背景窗口和组合规则全部冻结；
- 评价指标和分层规则提前写入配置；
- 只评价一次，不根据结果回头改模型。

没有 E3 时，项目最多报告开发结果和环境分层诊断，不能报告外部泛化。

## 6. 建议的实验分组方式

最小分组键：`experiment_id -> session_id -> scan_id -> event_id -> sample_id`。

模型切分时：

- 同一 session 的窗口不能跨 train/validation/test；
- 同一目标事件的窗口不能跨外层分组；
- 日期、场地和雷达配置应作为外层分组候选；
- 统计区间按 session 或 event bootstrap，不能把窗口数量当成独立样本数；
- 归一化和背景图只用训练/验证部分拟合，锁定测试不反向更新。

## 7. 采集后的放行条件

只有同时满足以下条件，才允许进入环境影响验证：

1. RSTM/原始 IQ 格式可解释，或明确记录为不可解释并降级任务；
2. 时间、顺序和同步合同通过；
3. 目标标签、背景标签和状态边界可追溯；
4. 每个目标条件都有同条件背景；
5. 气象和场地变量带时间、单位、传感器/来源和质量码；
6. 至少有一个不参与模型选择的新日期或新场地保留为 locked test；
7. 失败 session、异常天气、缺失传感器和未确认标签都保留，不得静默删除。

## 8. 责任分工

### 需要导师/场地方确认

- 雷达能否导出原始复数 H/V、设备格式和物理轴；
- 可用场地、雷达朝向、目标操作权限和安全终止条件；
- 是否有气象站、能见度/降水设备、视频和测距/测角设备；
- 能否安排多个日期或场地，并保留背景对照；
- 是否允许保存和共享原始数据及现场照片/地图。

### 项目内部准备

- 负责 `experiment_id/session_id` 规则、现场日志、manifest 和备份哈希；
- 先用学姐数据完成 RSTM 读取器和格式探针，不将其当正式实验；
- 维护环境字段契约和分层分析脚本；
- 每轮实验结束后生成质量报告和“允许/禁止结论”清单。
