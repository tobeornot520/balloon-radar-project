# 今晚组会备忘录：项目现状与下学期规划

日期：2026-08-26  
用途：今晚组内交流、任务对齐和会后行动记录

> 本文件是讨论备忘录，不替代 `PROJECT_CONTROL/TASK_BOARD.md`。申报书和答辩 PPT 中的内容属于项目背景与目标；只有经过设备、采集和实验验证后，才升级为正式结论。

## 一、会议目标

1. 先了解成员近况、兴趣、时间和困难，促进互相帮助。
2. 让全组了解当前项目已经做到哪里、下一步准备研究什么。
3. 在不把整个学期一次性排死的前提下，确定下学期方向和前两周的小任务。

建议时长：60--75 分钟。

## 二、会议流程

### 第一阶段：成员交流与互助（约 25 分钟）

每人可围绕以下问题自由发言：

- 最近主要在忙什么，预计下学期时间如何安排？
- 目前对项目了解多少，最感兴趣的方向是什么？
- 哪些技术、设备或协作环节不清楚？
- 自己能提供什么帮助，希望其他成员提供什么帮助？
- 是否有考试、竞赛、设备时间或其他现实限制？

会中把困难分为三类：

- 组员之间可以互相帮助的问题；
- 需要整理教程、手册或示例的问题；
- 需要导师、学长、设备方或合作公司确认的问题。

### 第二阶段：项目现状与未来方向（约 20 分钟）

当前项目主线是：

> 基于 H/V 双通道雷达数据，研究低空目标检测、距离--速度定位和复杂背景虚警抑制，并为后续空飘球载荷识别准备数据、特征和算法基础。

当前已经形成：

- H/V 功率、复数 RD、相对极化和多域特征接口；
- Simple FCN、H/V 双分支 DPG-FCN、背景校准和 ROI 精修模块；
- 分组评价、Joint Pd、Pfa、定位误差和因果边界审计；
- 数据采集合同、外场 SOP、课程讲义和技术手册。

当前不能直接宣称：

- 已完成空飘球有载/无载或载荷类型识别；
- H/V 已经是完整、标定的 `HH/HV/VH/VV` 全极化数据；
- complete-scan 结果是严格实时部署性能；
- 已经完成跨日期、跨场地或外部盲测泛化。

申报书和 PPT 支持的长期方向包括：实测数据集、多域融合、复杂背景/天气条件、载荷识别、实时性评价和技术演示。但天气识别、固定场地历史回归和指定边缘设备部署目前应作为候选增强方向，不能和主线同时硬性承诺。

## 三、下学期技术路线

### 阶段 0：数据合同与实验准备（前置阶段）

在正式建模前确认：

- 雷达型号、频段、PRF、波形、输出格式和配置导出；
- H/V 的收发含义、同步关系、复数 IQ 能力及幅相标定；
- 帧、脉冲、波束、扫描和文件之间的关系；
- 真实 UTC 时间戳、硬件序号、丢帧和时钟重置；
- 目标真值、气象、场地、对象构型和数据划分方式。

### 阶段 1：多域融合与公平增益证明

先建立可靠基线，再逐步增加信息域：

1. RD/Power2 单域基线；
2. 时域或原始回波特征；
3. 时频/微多普勒特征；
4. 经过物理确认的 H/V 相对特征；
5. 简单拼接；
6. 门控或交互注意力融合。

“多域优越”不能只看准确率，还应同时报告检测、分类、定位、最差场景和计算代价。模型容量、数据划分、阈值选择和训练预算必须尽量公平。

目标任务采用分层路线：

```text
目标/背景检测
  -> 空飘球/非空飘球
  -> 有载/无载
  -> 载荷状态或载荷类型
```

### 阶段 2：气象与场地因素建模

气象首先作为环境变量、分层变量和鲁棒性条件，而不是默认增加天气分类头。优先记录风速、风向、阵风、温度、湿度、气压、降水和能见度，并保留测量时间和设备信息。

场地先做定性档案，再做量化特征：开阔地/建筑区/树木区、遮挡、雷达朝向、强反射体、背景杂波强度、近零多普勒能量、谱熵和照片/平面图。

每个重要场地和天气条件下，都要有同日期、同配置的目标与背景对照，避免“场地或天气等于类别标签”的数据泄漏。

### 阶段 3：快速、因果和实时定位

依次完成：

1. 离线批处理可复现；
2. 严格因果流式回放；
3. 工作站实时运行；
4. 再评估是否需要具体边缘设备部署。

实时评估至少记录端到端 P50/P95/P99 延迟、吞吐、内存、丢帧、队列积压和持续运行稳定性。历史上下文必须规定首帧、历史不足、跨扫描清空、丢帧、重启和场地模型更新规则。

测速、测距和测角必须以真实设备观测能力为前提；若当前数据没有可靠角度信息，不能只靠网络输出就声称完成测角。

### 阶段 4：专家评审、锁定测试与应用

在读取锁定测试结果前，请导师、学长或有部署经验的人员审阅：任务定义、数据划分、单域/多域公平性、指标、阈值、实时性和表述边界。

最终评估至少包括：

- 识别：Pd、Pfa、F1、召回率和混淆矩阵；
- 定位：距离、速度、角度误差和严重失败率；
- 泛化：跨日期、场地、天气和目标实例；
- 工程：延迟、吞吐、内存、丢帧和持续运行。

模型、特征、阈值、后处理规则和主指标冻结后，锁定集只评价一次。

## 四、外场采集安排

### 第一次外场建议

在合作公司场地和设备情况尚未确认时，第一次建议由你和两位熟悉的同学组成三人小组，定位为“设备学习、场地勘察和最小试采”，不是正式大规模采集。

建议角色：

- 你：实验负责人、对外沟通、配置和异常记录、停止决定；
- 同学 A：跟随设备方学习雷达操作并记录流程；
- 同学 B：视频、目标状态、文件核对、备份和现场日志。

正式 Pilot 至少需要实验负责人、雷达操作员、目标操作员、真值/视频/数据/安全记录等明确责任。若合作公司提供雷达操作员，三名学生可以承担其余工作；否则再增加成员或候补。

### 分阶段采集

1. 设备 capability 与连续写盘测试；
2. 雷达--视频--真值同步和 H/V 标定；
3. 无球 dry run 与纯背景采集；
4. 四场景 Pilot；
5. Pilot 质检后再进行正式 development/validation 采集；
6. 最后保留未参与开发的 locked test。

四场景 Pilot：

- 纯背景；
- 无载球稳定状态；
- 同一球体、同一载荷稳定状态；
- 同一球体和载荷的摆动或自然运动。

每种场景建议至少 3 个独立重启 session，每段连续 2--5 分钟，并配同条件背景对照。第一次 Pilot 的主要目的不是追求样本数量，而是发现同步、标定、标签、备份和安全问题。

## 五、采集数据清单

每个实验 session 不只是一个雷达文件，而是一组互相引用的同步数据：

| 数据类别 | 主要内容 | 用途 |
|---|---|---|
| 雷达 | H/V 原始 IQ、配置、标定编号、扫描关系 | RD、极化、时频、多域特征 |
| 时间 | UTC、硬件序号、scan/frame/pulse ID、丢帧、重启 | 历史关系、因果模型、实时回放 |
| 真值 | 目标存在、类别、距离、速度、轨迹、状态起止和误差 | 检测、定位、分类评价 |
| 气象 | 风速、风向、阵风、温湿度、气压、降水、能见度及时间 | 环境分层和鲁棒性分析 |
| 场地 | `site_id`、雷达位置/朝向、地物、遮挡、照片、纯背景 | 杂波建模和跨场地评价 |
| 对象 | 球体、载荷、绳长、质量、材料、安装和状态 | 有载/无载及对象归因 |
| 运行 | 解码、预处理、推理、后处理耗时，资源和积压 | 实时性评价 |

## 六、今晚需要形成的决定

建议今晚先决定以下事项，不必一次性决定所有细节：

- 是否同意以上四阶段技术路线；
- 第一阶段的主任务是检测，还是同时启动空飘球/非空飘球分类；
- 是否成立三人外场准备小组；
- 谁负责联系导师、学长和合作公司确认设备、场地、人员和时间；
- 谁负责整理采集字段、标签和真值清单；
- 谁负责复现当前 Power2/DPG 基线和后续单域模型；
- 谁负责实时性指标和部署测试方案；
- 开学后前两周每个人提交什么小产物。

## 七、会后第一批行动

1. 向导师/学长发送设备与场地事实确认清单。
2. 建立三人外场准备小组和一名候补成员。
3. 根据真实合作条件修订 Pilot 日期、人员和仪器清单。
4. 冻结第一版采集 manifest、对象表、气象表、场地表和运行日志表。
5. 为多域模型确定 Power2、RD、时频和相对 H/V 的最小公平比较方案。
6. 约定下一次会议审阅采集合同和第一阶段模型实验设计。

## 八、当前总判断

项目应采用“先建立可解释、多域、可公平比较的模型，再量化气象和场地影响，之后推进因果实时定位，最后进行专家评审和应用验证”的主线。

物理建模贯穿前两阶段，用来决定采什么、提什么特征和如何解释结果；复杂全波电磁、CFD 和完整全极化分解暂列探索任务，不作为下学期主线前置条件。
