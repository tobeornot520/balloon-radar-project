# 2026 秋季项目执行路线与分工表

版本：2026-09-12  
适用期：2026 秋季学期，按学期周次执行；具体外场日期以设备方和导师确认结果为准。  
文件性质：执行计划，不替代正式状态源。

## 0. 如何使用本文件

本文件把已有的路线、外场 SOP 和会议讨论整理成可执行的学期计划，回答三个问题：

1. 进入采集前，必须先准备什么；
2. 采集、建库、模型、实时性和论文任务如何排成先后顺序；
3. 组员按什么角色分工、每阶段交付什么、怎样判断完成。

正式任务状态、负责人和验收门仍以 [`TASK_BOARD.md`](TASK_BOARD.md) 为准；当前事实和研究边界以 [`docs/CURRENT_STATUS.md`](../docs/CURRENT_STATUS.md) 为准。两者与本计划不一致时，先更新任务台账，再修改本文件。

当前总判断：项目可以立即进入“设备事实确认和采集准备”，但还不能直接进入大规模正式采集。H/V 通道含义、原始 IQ、真实时间顺序、标定和场地条件尚未由外部证据确认，主方向仍为 `4/6 BLOCKED_EXTERNAL`。

## 1. 学期总目标

### 必须完成的主线

```text
设备/采集事实
  -> 可审计 Pilot 数据
  -> Power2/RD 单域基线
  -> 多域融合公平比较
  -> 气象与场地分层鲁棒性
  -> 因果流式与实时性评估
  -> 锁定评价、论文和汇报交付
```

### 研究问题的分层顺序

不得跳过前一层直接训练最后一层：

```text
目标/背景检测
  -> 空飘球/其他目标
  -> 有载/无载
  -> 载荷类别或运动状态
```

当前 UAV/背景结果只能作为检测前端和方法开发证据，不能直接改写为空飘球载荷识别结果。

### 本学期不作为硬性主线的内容

- 天气分类头：天气先作为元数据、分层变量和鲁棒性条件；
- 完整全波电磁、CFD 或复杂散射反演：可做小型解释性探索，不作为采集和模型主线前置条件；
- 在已消费测试集上继续调参、扩结构或重复确认性比较；
- 在没有真实时间戳、PRF 和连续慢时间 IQ 时宣称物理微多普勒或严格实时。

## 2. 分阶段时间表

日期只作参考锚点，若设备方时间变化，保持阶段顺序和放行条件不变。

| 阶段 | 学期周次/参考时间 | 主要目标 | 必须交付 | 放行条件 |
|---|---|---|---|---|
| A0 | W0，9/12--9/18 | 组织和事实清单 | 角色表、设备问题单、外场候选日期、风险清单 | 导师/设备方确认联系人和下一次沟通时间 |
| A1 | W1--W2，9/19--10/02 | Capability 能力摸底 | 雷达配置、H/V 最小样例、300 s 写盘报告、设备答复表 | `CAP_RADAR_ID`、原始 H/V、扫描关系和写盘能力有证据 |
| A2 | W3--W4，10/03--10/16 | 同步与标定台架 | 5 次以上同步事件、UTC 映射、H/V 标定报告、`calibration_id` | 同步 P95 <= 50 ms、最大值 <= 100 ms；标定重复性达 SOP 门限 |
| A3 | W5--W6，10/17--10/30 | 无球 Dry Run | 纯背景、视频、真值、manifest、双份备份、回放报告 | `capture` 和 `causal` 合同通过；无未解释丢帧/时钟重置 |
| A4 | W7--W8，10/31--11/13 | 四场景 Pilot | 每场景至少 3 个独立 session；接受/拒绝清单 | 四场景链路完整；失败项形成 `REPEAT` 或 `REDESIGN` 决策 |
| A5 | W9--W10，11/14--11/27 | 数据集 V1 与基线 | 数据卡、分组 manifest、Power2/RD 基线、数据质量报告 | 目标/背景同条件对照；session/date/site 分组可审计 |
| A6 | W11--W12，11/28--12/11 | 多域融合公平比较 | RD、时域/时频、相对 H/V、拼接/门控消融和复杂度表 | 固定 split、预算、阈值规则；同时报告检测、定位、最差组和资源 |
| A7 | W13--W14，12/12--12/25 | 环境鲁棒性与因果回放 | 气象/场地分层报告、past-only 训练/回放、延迟测试 | 不把日期/场地当类别捷径；因果顺序由硬件证据支持 |
| A8 | W15--W16，12/26--1/08 | 冻结评价与论文交付 | 冻结配置、锁定测试报告、论文初稿、组内汇报包 | 模型/特征/阈值/后处理/指标冻结后只评价一次 |

若 A1--A4 任一门失败，后续阶段不跳过，转入 `REPEAT` 或 `REDESIGN`。学期末未通过锁定门时，应如实交付“内部开发结果 + 数据链限制 + 下一阶段计划”，不把计划写成已完成成果。

### 2.1 多轮实验组织

本项目不是一次外场采集，而是由目的不同、状态不同的多轮实验组成。每轮都可以包含多个日期和多个 `session_id`；“一轮”描述实验目的，“session”描述一次连续采集。

| 实验轮次 | 对应阶段 | 目的 | 数据状态 | 是否用于模型开发 |
|---|---|---|---|---|
| E0 设备与无球演练 | A1--A3 | 验证雷达配置、写盘、同步、视频和备份链路 | `engineering` / `dry_run` | 只用于接口和质量检查，不用于性能结论 |
| E1 Pilot | A4 | 用四类场景验证标签、真值和同条件背景对照 | `development` | 可用于发现问题和初步开发，不得作为盲测 |
| E2 扩展采集 | A5--A7 | 增加日期、场地、气象、对象和运动状态，形成正式 V1/V2 数据集 | `development` / `validation` | 用于训练、调参和分层验证；按 session/date/site 分组 |
| E3 锁定评价 | A8 | 在模型、特征、阈值和后处理冻结后进行最终评价 | `locked_test` | 只评价一次，不回流调参 |

实验轮次可以因设备或天气重复，但重复采集必须新建 `session_id`，并记录重复原因、配置、标定 ID 和数据版本。E1 失败时重做 E1，不应直接把未通过的样本混入 E2；E3 若条件不满足则保持未执行状态，不得用 E1/E2 的结果代替。

## 3. 采集前置准备清单

### 3.1 设备和人员

在第一次去现场前完成：

- 雷达型号、频段、PRF、带宽、脉冲数、距离门、软件和固件版本登记；
- H/V 的收发含义、同时/交替采样方式、时间差和相干性说明；
- 一帧、波束、扫描、文件和硬件序号的对应关系；
- 原始 IQ 的变量名、维度、数据类型、量化和缩放系数；
- 连续 300 s 采集和写盘吞吐测试；
- 视频、UTC/GPS/RTK、测距/测角和气象设备确认；
- 场地授权、遮挡/强反射体记录、人员安全边界和停止条件；
- 实验负责人、雷达操作、目标操作、真值记录、数据备份和安全责任人。

逐项填写 [`field_capability_response_template_v1.csv`](../configs/field_capability_response_template_v1.csv)，不要用文件名、MAT header 或文件 mtime 猜测设备事实。

### 3.2 数据和记录工具

现场至少准备以下空白表：

- `configs/data_collection_manifest_template_v1.csv`
- `configs/pilot_session_log_template_v1.csv`
- `configs/field_sync_event_template_v1.csv`
- `configs/field_readiness_evidence_template_v1.csv`
- `configs/pilot_scenario_matrix_v1.csv`

受控数据目录建议固定为：

```text
collection_root/
  raw_iq/ video/ truth/ radar_configs/ calibration/
  weather/ manifests/ session_logs/ hashes/
```

原始 IQ、视频和真值首次落盘后只读；纠错通过新版本 manifest 或派生标签完成，不覆盖原件。至少保留两份独立备份，并在现场生成哈希清单。

### 3.3 第一次采集的目标

第一次外场不是追求样本量，而是回答“这条采集链能否被解释、同步、回放和复用”。最小任务是：

1. 固定配置采一份 H/V 原始样例；
2. 连续写盘至少 300 s；
3. 完成可见同步事件；
4. 采纯背景和一个可确认运动目标；
5. 现场读回文件、检查 H/V、时长、序号和视频；
6. 复制到第二介质并记录异常。

## 4. Pilot 和正式数据集设计

### 4.1 第一轮 Pilot 四场景

| 场景 | 目标 | 最低要求 |
|---|---|---|
| 纯背景 | 估计背景虚警和链路稳定性 | 3 个独立 session，2--5 min/次 |
| 无载球 | 建立球体本身参考 | 3 个独立 session，全程视频 |
| 有载稳定 | 隔离载荷的稳定差异 | 同一球体/载荷，3 个独立 session |
| 有载摆动或自然运动 | 检查状态标签和时域链路 | 3 个独立 session，记录状态起止 |

目标场景必须有同日期、同场地、同 `radar_config_id` 和同 `calibration_id` 的背景对照。第一轮只固定一个 Pilot 载荷，不同时改变球体、载荷、距离、悬挂和运动方式。

### 4.2 正式数据集至少要记录

| 类别 | 必要字段 | 用途 |
|---|---|---|
| 雷达 | H/V IQ、配置、PRF、帧/波束/扫描关系 | RD、时频和极化特征 |
| 时间 | UTC、硬件序号、scan/frame/pulse ID、丢帧、重启 | 因果上下文和实时评估 |
| 真值 | 目标存在、类别、距离、速度、方位、状态起止 | 检测、定位和分层识别 |
| 环境 | 风速、风向、阵风、温湿度、气压、降水、能见度及时间 | 分层鲁棒性和混杂检查 |
| 场地 | `site_id`、朝向、遮挡、强反射体、照片/平面图 | 杂波和跨场地评价 |
| 对象 | 球体、载荷、质量、绳长、安装和状态 | 有载/无载归因 |
| 运行 | 配置版本、标定 ID、处理/推理耗时、资源、备份哈希 | 可追溯和实时性 |

### 4.3 数据划分

- 按 `session_id`、日期、场地或对象实例做外层分组，不能把同一 session 切片后随机分到不同集合；
- development 用于设计和调参，validation 用于冻结前选择，locked_test 在模型/阈值/特征/组合规则冻结后只评价一次；
- 每个重要日期、场地和雷达配置都应同时有目标和背景，防止类别与环境完全耦合；
- Pilot 全部标为 `development`，不能因为结果好看升级为 locked test。

## 5. 长线工作包与组员分工

人员姓名在第一次团队确认会后填入任务板；先按角色分工，避免“所有人都负责”导致无人验收。

| 工作包 | 建议角色 | 主要职责 | 阶段产物 | 对应任务 |
|---|---|---|---|---|
| P0 项目与物理把关 | 负责人/你 | 对外沟通、研究问题、设备事实、对象和真值合理性、停止决定 | 事实确认、场地/对象记录、决策纪要 | D02、D12、D13 |
| P1 外场与安全 | 外场负责人 + 雷达操作员 | 架设、配置、同步、标定、场地安全、session 执行 | capability、sync、calibration、dry run、Pilot 证据 | D12、D13 |
| P2 数据工程 | 数据负责人 | 目录、manifest、文件完整性、备份、标签和分组 | 数据卡、manifest、质量报告、拒收清单 | D03、D15 |
| P3 基线与多域模型 | 算法负责人 | Power2/RD 基线、时域/时频/HV 特征、融合和公平消融 | 训练配置、主表、消融表、复杂度表 | D05、D06、D07 |
| P4 物理与特征解释 | 物理/信号负责人 | FFT/STFT、极化量命名、气象/场地变量和可解释性 | 特征定义、物理假设、限制说明 | D02、D11、D12 |
| P5 评价与实时部署 | 评价/工程负责人 | Pd/Pfa/Joint Pd、定位、worst-group、因果回放、延迟吞吐 | 冻结评价、延迟报告、失败案例 | D03、D07、D09 |
| P6 论文与汇报 | 论文负责人 | 论文主线、图表、周报、学长/导师汇报和复现说明 | 会议稿、论文版本、证据索引 | D14、D15、D16 |

一个人可以兼任多个角色，但以下组合应尽量分开：雷达操作与目标操作、实验执行与锁定测试评价、模型选择与最终盲测记录。

### 每个工作包的长期职责

- P0 决定“研究问题和物理事实是否成立”，不负责替设备猜参数；
- P1 决定“数据是否按 SOP 采到”，不负责把失败 session 修成通过；
- P2 决定“数据是否可追溯和可分组”，不负责根据结果修改标签；
- P3 决定“模型是否有公平增益”，不只追求最高单一指标；
- P4 决定“特征能否这样命名和解释”，未标定量统一使用相对/类比命名；
- P5 决定“结果是否满足评价合同和实时约束”，不把 complete-scan 写成实时；
- P6 决定“论文和汇报是否越过证据边界”，不隐藏负结果和外部阻塞。

## 6. 各阶段验收产物

### A0--A2：采集链验收

- 设备事实答复表和附件；
- H/V IQ 内容探针报告；
- 300 s 连续写盘与丢帧报告；
- 至少 5 次同步事件及误差统计；
- H/V 标定重复性和唯一 `calibration_id`。

### A3--A4：Pilot 验收

- 每个 session 一个不重复的 `session_id`；
- 完整 manifest、视频、真值、气象和配置引用；
- capture/causal 审计结果；
- 接受、拒绝和整改清单；
- 两份备份哈希一致。

### A5--A6：模型验收

- Power2 和 RD 强基线；
- 同 split、同训练预算、同阈值规则的单域/多域比较；
- Score Pd、Joint Pd、Pfa、定位误差、最差组和资源占用；
- 逐域消融、复杂度和失败样本分析；
- 结果绑定 `experiment_id`、manifest、config、commit 和摘要。

### A7--A8：交付验收

- 气象/场地分层报告和混杂检查；
- 真实顺序支持的 causal 流式回放；
- P50/P95/P99 延迟、吞吐、内存、丢帧和持续运行报告；
- 冻结模型、阈值、特征、后处理和指标；
- locked test 一次性报告、论文主表和可复现说明。

## 7. 每周协作机制

每周一次 30--45 分钟短会，只回答四件事：

1. 上周交付物是否存在且可审查；
2. 本周唯一最重要的下一步是什么；
3. 哪个任务被外部事实阻塞；
4. 是否触发停止或重新设计。

每位成员每周提交一条结构化记录：`task_id`、本周产物、证据路径、阻塞、下周动作。正式状态写入 `TASK_BOARD.md`，会议讨论背景写入 `PROJECT_CONTROL/meetings/`，实验事实写入 `PROJECT_LOG.md`。

## 8. 立即执行的 7 天清单

截至 2026-09-12，建议下一周只做以下事项：

1. 确认导师/设备方联系人、场地权限和可用日期；
2. 由 P0/P1 发出设备能力确认单；
3. 由 P2 建立受控 `collection_root` 和空白 manifest/session 表；
4. 由 P3/P4 准备 Power2、RD 和最小时域接口的无数据 smoke；
5. 由 P5 冻结采集质量、同步误差、丢帧和备份验收字段；
6. 由 P6 准备第一次组会的一页路线图和当前边界说明；
7. 会议结束后把姓名、任务 ID、截止周次和验收人回填任务板。

本周不做：正式大规模采集、不启动空飘球分类训练、不在旧测试集上继续调参、不把设备未知项写成已确认事实。

## 9. 停止与重新设计规则

出现以下任一情况，当前阶段停止并保留诊断材料：

- H/V 缺失、通道映射不清或只有处理后图片；
- 没有真实时间戳/硬件序号，仍试图声称 causal 或实时；
- 同步误差超限、状态起止无法确认或视频不可用；
- 连续写盘丢帧、饱和、缓存溢出或第二备份校验失败；
- 目标与背景被日期、场地、配置完全分开，无法做同条件对照；
- 复杂极化特征缺少相干/标定依据却被写成绝对物理量；
- 只能靠修改标签、删除失败样本或查看锁定结果后调参才能通过。

处理方式只有三种：`PASS` 进入下一阶段，`REPEAT` 修复后重做当前阶段，`REDESIGN` 收缩研究问题并更新数据合同。模型准确率不能覆盖采集链失败。
