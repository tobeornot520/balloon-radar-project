# 复杂气象与环境方向：初步调研与实验设计

版本：V1.0  
日期：2026-09-18  
适用角色：环境、场地、干扰和鲁棒性方向负责人  
当前状态：调研任务，不代表已经批准训练环境模型或进行外场采集

## 一、先给结论

把环境因素分成“快变响应”和“慢变先验”是合理的，但建议再加一个独立的“干扰压力测试”层：

```text
快变环境响应：风、阵风、降水、能见度、短时背景变化、系统状态
        -> 在线质量判断、背景校准、鲁棒性分层、因果上下文

慢变场地先验：地物、遮挡、固定强反射体、雷达朝向、长期背景占用
        -> 场地档案、背景基线、候选风险图、跨场地泛化检查

外部干扰压力测试：已知或可控的电磁/设备/链路干扰
        -> 失败模式、抗干扰压力测试、停止和报警规则
```

这三层不能混成一个“环境模型”。天气变化、固定场地杂波和电磁干扰的物理来源、时间尺度、可观测变量和处理方法都不同。

当前最稳妥的研究顺序是：

1. 记录环境和场地变量，确认它们是否与背景虚警、目标漏检或定位误差相关；
2. 用同条件目标/背景对照和跨日期/跨场地分组，排除环境与类别完全耦合；
3. 先做分层评价和轻量校准，再决定是否把环境变量接入模型；
4. 最后再做场地背景图、风场辅助或干扰仿真。

## 二、你的两个想法分别应怎样收敛

### 2.1 快变环境：不是“天气分类”，而是环境条件下的检测可靠性

风场、阵风、降水和能见度可能同时影响：

- 空飘球的速度、摆动、旋转和轨迹；
- 地物、树木、线缆等背景的运动或散射变化；
- 雷达回波强度、噪声底和虚警分布；
- 视频、GPS/RTK、测距和其他真值设备的可用性。

因此，第一阶段不应直接把天气做成一个分类头，而应回答：

1. 环境变量是否改变背景虚警率或分数分布？
2. 环境变量是否改变目标的检测率、定位误差或运动状态？
3. 在只能使用当前时刻和历史信息的条件下，环境变量能否帮助校准阈值或背景分数？
4. 环境变量加入后，是否降低了某些条件下的虚警，同时没有损失目标保护？

风场可以作为目标运动和状态标签的解释变量，也可以作为模型辅助输入；但不能因为“风大”就直接推断某个回波一定来自空飘球。需要同步目标真值和背景对照。

### 2.2 慢变环境：优先做“经验背景地图”，不要一开始做完整物理反演

雷达部署位置相对固定，确实可以利用长期纯背景数据建立场地档案，例如：

- 距离/方位或距离/速度网格上的背景占用率；
- 固定强反射体、建筑、树木、地面和遮挡区域；
- 近零多普勒能量、谱熵、峰稳定性等背景摘要；
- 雷达朝向、俯仰、观测扇区和场地照片/平面图的对应关系。

这首先是**数据驱动的场地背景先验**，不等于完整的雷达遥感地图，也不等于已经建立了传播、散射或 RCS 物理模型。它可以帮助回答“这个位置长期容易出背景峰吗”，但有两个风险：

- 模型可能记住场地位置，换场地后失效；
- 如果目标只在某个场地采集，背景地图会把场地和类别混在一起。

所以场地先验必须在训练/验证中按 `site_id` 隔离，并保留至少一个未参与设计的新场地或新日期作为后续锁定评价。

### 2.3 外部干扰：先区分“干扰源”与“自然背景杂波”

“干扰”至少包括三类：

1. **自然或场地杂波**：建筑、树木、地面、固定设施、近零多普勒结构；
2. **目标/环境运动干扰**：鸟、车辆、摇摆物、风致运动结构；
3. **电磁或系统干扰**：其他发射源、串扰、饱和、缓存溢出、时钟异常、链路丢帧。

三者不能使用同一种模型。没有真实干扰源记录时，仿真只能叫“压力测试”，不能写成现场干扰泛化证据。若要做信号源建模，必须记录频段、出现时间、可控开关、接收端表现和安全/合规边界。

## 三、当前项目对你的正式研究问题

建议先写成以下四个问题，而不是直接写“建立气象和环境模型”：

### R1：环境是否解释当前检测失败？

对目标漏检、背景虚警和定位大误差，检查它们与风速、阵风、降水、场地、遮挡、背景能量和雷达运行状态的关系。

输出不是新的准确率，而是一份失败模式表：

| 失败类型 | 需要检查的环境变量 | 需要的证据 |
|---|---|---|
| 背景虚警增加 | 场地、近零多普勒、风、树木/建筑运动、系统状态 | 同条件纯背景、环境时间戳、回波图和运行日志 |
| 目标漏检 | SNR、距离、风、目标运动状态、遮挡 | 目标真值、视频、轨迹、气象和原始 IQ |
| 距离/速度误差变大 | 目标摆动、风向、速度、同步误差、分辨率 | 定位真值、状态起止、同步事件和误差记录 |
| 分数分布漂移 | 日期、场地、配置、标定、噪声底 | session 分组、配置/标定 ID、背景统计 |

### R2：环境变量是否能改善校准而不是制造捷径？

先比较三种方案：

1. 不使用环境变量的 Power2/RD 基线；
2. 只用当前背景和历史上下文的背景校准；
3. 在因果可用的前提下加入风、降水等环境摘要的轻量校准。

评价必须同时报告 `Pfa`、`Score Pd`、`Joint Pd`、定位误差、最差环境组和延迟。不能只报告环境分类准确率或 pooled AUC。

### R3：固定场地先验是否真的有帮助？

建立场地背景图后，至少比较：

- 无场地先验；
- 只使用当前 session 的背景统计；
- 使用历史背景图；
- 新场地/新日期上不使用或受限使用历史图。

如果历史图只在原场地有效，应把它定位为“固定部署的场地适配模块”，不能写成跨场地泛化方法。

### R4：干扰压力测试能否发现系统边界？

先建立干扰目录和可观测特征，再决定是否做可控注入或仿真。每种干扰都要记录：来源、时间、频段/形态、是否可重复、是否影响 H/V、是否影响时间顺序和是否安全可控。

## 四、初步调研应该交付什么

第一轮不要训练模型，先提交六份小材料：

### 4.1 环境变量字典

建议字段：

| 字段 | 示例 | 必须说明 |
|---|---|---|
| `variable_id` | `wind_speed_10m` | 唯一名称 |
| 中文名称 | 10 m 风速 | 物理含义 |
| 单位 | m/s | 单位和量程 |
| 来源 | 风速仪/气象站/雷达配置 | 设备和证据 |
| 时间分辨率 | 1 s/1 min/session | 采样和同步方式 |
| 空间位置 | 雷达旁/目标附近/场地外 | 代表哪个位置 |
| 因果可用性 | 当前/历史/事后 | 是否能用于在线模型 |
| 用途 | 分层/校准/解释 | 不默认作为输入 |
| 缺失处理 | 缺失/插值/拒收 | 不允许静默填补 |

最低环境字段建议为：风速、风向、阵风、温度、湿度、气压、降水、能见度、测量时间和设备信息。探空、风廓线和雨滴谱先列为可选项。

### 4.2 场地档案模板

每个 `site_id` 至少记录：

- 雷达经纬度或受控位置、朝向、俯仰和观测扇区；
- 开阔地/建筑区/树木区/水面/道路等定性类别；
- 建筑、树木、杆塔、金属设施、地面和遮挡；
- 现场照片、简图和可公开的平面示意；
- 纯背景 session、时间段和雷达配置；
- 可能的电磁源和设备运行状态；
- 哪些条件是长期固定，哪些会随季节或施工改变。

### 4.3 环境--目标--背景对照矩阵

至少做成如下形式：

| 日期 | 场地 | 天气/风况 | 目标场景 | 背景对照 | 配置/标定 | 可用性 |
|---|---|---|---|---|---|---|
| D1 | S1 | 低风 | 无载/有载 | 同时段纯背景 | 同一 ID | 待采 |
| D1 | S1 | 阵风 | 摆动/自然运动 | 同时段纯背景 | 同一 ID | 待采 |
| D2 | S1 | 不同风况 | 目标重复 | 同场地背景 | 同一 ID | 待采 |
| D3 | S2 | 不同背景 | 目标重复 | S2 背景 | 同一 ID | 待采 |

这张表的目的不是马上确定样本总数，而是防止“目标只在晴天、背景只在阴天”这种环境泄漏。

### 4.4 环境影响的可检验假设

先写 3--5 条可证伪假设，例如：

- H1：阵风增强时，球体运动状态变化，目标速度/定位误差分布发生变化；
- H2：某类场地固定反射体造成稳定背景峰，其风险位置在纯背景图中可重复出现；
- H3：环境变量加入背景校准后，最差环境组的 Pfa 降低，同时 Joint Pd 不下降；
- H4：历史场地先验在原场地有效，但跨场地收益减弱；
- H5：无真实时间戳时，环境变量不能被用于严格因果部署结论。

每条假设后面都写数据、对照、指标和可能的否定结果。

### 4.5 方法路线一页图

建议画成：

```text
雷达原始 IQ/Power2/RD + 时间戳
             |
       环境与场地元数据
       /        |        \
  快变摘要   场地背景图   干扰目录
       \        |        /
       基线 / 校准 / 压力测试
             |
   Pd、Pfa、Joint Pd、定位、延迟、最差组
```

图中要明确：环境变量首先用于分层和解释；只有在新数据和因果合同满足后，才作为模型输入。

### 4.6 一页风险和边界表

| 计划 | 主要风险 | 触发条件 | 降级方案 |
|---|---|---|---|
| 风场辅助 | 没有同步风场或目标真值 | 只有手工天气描述 | 仅作分层变量，不接模型 |
| 场地背景图 | 场地和类别耦合 | 目标只在一个场地 | 只做背景诊断，暂停泛化声明 |
| 回波/干扰模型 | 缺少源参数或标定 | 只能凭经验假设信号 | 做合成压力测试，不作现场结论 |
| 在线校准 | 没有真实顺序 | 只有文件名时间/mtime | 离线 session 诊断，不称实时 |
| 风险分箱 | 样本过少 | 某天气组只有少数 session | 报连续变量和不确定性，不硬分组 |

### 第 1 步：读项目内文件，先建立共同语言

优先阅读：

1. [`EXPERIMENT_PREPARATION_DATA_REQUIREMENTS_ZH.md`](../EXPERIMENT_PREPARATION_DATA_REQUIREMENTS_ZH.md) 的 D4、D5、D7 和环境字段；

3. [`MULTIDOMAIN_FEATURE_GATE_V1.md`](../../docs/MULTIDOMAIN_FEATURE_GATE_V1.md) 的日期/场地混杂和特征放行门；
4. [`NEW_DATA_COLLECTION_PROTOCOL.md`](../../docs/NEW_DATA_COLLECTION_PROTOCOL.md) 的 `capture`、`causal`、`locked_evaluation`；
5. [`2026-08-26_PROJECT_PLANNING_MEMO.md`](../meetings/2026-08-26_PROJECT_PLANNING_MEMO.md) 的环境与场地建模部分。

阅读产物：一页“当前项目允许说什么、不能说什么”的边界表。

### 第 2 步：调研四个主题，而不是泛泛搜索天气雷达

建议检索方向：

- `weather effects on radar target detection clutter`
- `wind induced motion radar balloon target tracking`
- `radar site clutter map background suppression`
- `environment conditioned radar detection false alarm calibration`
- `radar interference classification mitigation controlled experiment`
- `causal online clutter adaptation radar`

每篇资料只记录五项：研究对象、雷达数据级别、环境变量、对照/划分、能否迁移到本项目。不要只摘摘要和网络结构。

### 第 3 步：做一个“变量--机制--实验”表

格式如下：

| 环境变量 | 可能机制 | 可观测证据 | 最小实验 | 评价 |
|---|---|---|---|---|
| 阵风 | 球体摆动、树木/线缆运动 | 风速、状态视频、RD/时域变化 | 同场地低风/阵风目标与背景配对 | Pfa、Joint Pd、定位误差 |
| 降水 | 衰减、散射、噪声和能见度下降 | 降水记录、视频、回波统计 | 同配置不同降水条件 | 分层 Pd/Pfa、数据完整性 |
| 固定建筑 | 稳定强反射/遮挡 | 场地图、背景峰位置 | 长时纯背景 + 目标/背景对照 | 峰稳定性、跨日期/场地 |
| 电磁源 | 频带串扰、饱和或异常谱形 | 频段/时间/设备日志 | 仅在安全可控时做压力测试 | 漏检、误警、链路质量 |

### 第 4 步：设计最小 Pilot，而不是先建大模型

第一轮只需要验证：

1. 环境传感器是否能与雷达、视频和真值同步；
2. 纯背景中的场地结构是否可重复；
3. 目标在不同运动状态下是否有可审计标签；
4. 环境变化是否足以形成有意义的分层；
5. 记录缺失、不同步和设备异常是否能被识别。

只有这些通过，才进入环境条件下的校准或融合模型。

## 六、第一阶段明确不做的事

- 不把天气标签直接做成新的分类头；
- 不用单次天气描述替代连续测量；
- 不在没有真实时间顺序时训练 past-only 或宣称实时环境适配；
- 不把固定场地背景图写成跨场地泛化模型；
- 不在没有干扰源事实时声称完成电磁干扰识别；
- 不做完整全波电磁、CFD 或高精度风场反演作为外场采集前置条件；
- 不在当前已消费测试数据上通过环境特征反复调参；
- 不把相关性写成风场导致某种目标类别的因果证明。
