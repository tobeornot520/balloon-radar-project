# 气象与场地因素模型规划 V1

版本：V1.0  
日期：2026-09-25  
定位：理论模型、字段设计和验证路线；不是已经完成的训练结果

## 1. 研究问题先收窄

我们不先问“天气分类准确率是多少”，而先问两个可验证的问题：

1. 在目标和背景条件可比时，气象变化是否改变 `Pfa`、`Pd`、`Joint Pd` 或定位误差？
2. 固定站点的场地结构是否形成稳定的背景风险区域，以及加入这个先验后是否能减少虚警而不损失目标？

天气是快变条件，场地是慢变条件。二者都应该先作为**条件变量/先验变量**，再决定是否进入检测网络。

## 2. 总体观测模型

对一个时间窗口或目标事件，记：

```text
X      雷达信号（IQ、Power2、RD 或时频表示）
W(t)   气象条件（风、阵风、降水、能见度、温湿压）
G(s)   场地条件（site、方位、遮挡、背景图、固定反射体）
T      目标状态和观测几何（类别、距离、速度、姿态、运动状态）
C      雷达配置、标定和采集质量
Y      模型输出或评价结果（分数、检测、定位误差）
```

第一层信号模型可以写成：

```text
X = F(T, W(t), G(s), C) + noise
```

评价层不直接把相关性叫因果，可先写成：

```text
Y = f_signal(X) + h_weather(W) + h_scene(G)
    + h_interaction(W, G, range, angle) + error
```

这里的 `h_weather` 和 `h_scene` 是待验证的影响项，不是预先假设它们一定有效。

## 3. 气象数据模型

### 3.1 原始变量

必须保留原始观测、单位、传感器高度、采样间隔、质量标记和缺失原因。建议字段见：

`configs/environment_context_observation_schema_v1.json`

核心变量：

| 变量 | 形式 | 理论作用 | 备注 |
|---|---|---|---|
| 风速均值 | m/s | 影响漂浮目标速度、摆动和背景柔性物体运动 | 不等于目标高度风速 |
| 阵风 | m/s | 代表短时突变和运动不稳定 | 与均值分开 |
| 风向 | 度 | 决定目标运动方向和场地反射方向关系 | 需要真北/传感器朝向 |
| 风矢量 u/v | m/s | 适合连续建模和与雷达方位做夹角 | 由风速/风向统一转换 |
| 温度/湿度/气压 | 摄氏度/%/hPa | 传播、设备状态和目标状态的协变量 | 第一阶段不强行解释每个物理机制 |
| 降水率 | mm/h | 天气回波、噪声底和传播变化 | 没有仪器时不填 0 |
| 能见度 | m | 主要是观测/视频质量和天气分层变量 | 不能直接当传播损耗量 |

### 3.2 派生变量

所有派生变量必须由时间窗内的原始观测计算，不能使用事件结束后的未来值：

- `wind_speed_mean_1m`、`wind_speed_std_1m`、`wind_gust_ratio`；
- `wind_u`、`wind_v`、`wind_relative_to_radar_deg`；
- `precip_present`、`precip_rate_log1p`；
- `visibility_log1p`；
- 温湿压标准化值和缺失指示变量；
- `weather_quality_flag`、传感器断线时长和最近有效观测年龄。

如果没有垂直风廓线或目标高度对应的观测，只能把这些变量命名为近地面气象条件，不能升级为“目标所在高度风场”。

## 4. 场地数据模型

### 4.1 固定场景层

每个 `site_id` 建立一个版本化场地档案：

- 雷达位置、高度、朝向和配置版本；
- 方位/俯仰方向上的遮挡角、可见天空比例；
- 建筑、树木、地面、金属设施、水面和其他强反射体的类别与大致范围；
- 现场照片、平面图、许可范围和采集日期；
- 可用 DEM/DSM/遥感资料的来源、分辨率和版本。

地图资料是几何先验，不直接等价于回波强度。

### 4.2 经验背景层

从**纯背景** IQ/RD 中生成，不使用目标事件，也不读取测试期未来数据：

- `background_power_q50/q90/q99`：每个距离-方位或距离-Doppler 单元的背景分位数；
- `background_occupancy`：超过训练期背景阈值的比例；
- `background_peak_stability`：重复背景扫描中峰出现的一致性；
- `background_zero_doppler_fraction`：近零多普勒能量比例；
- `background_risk_at_candidate`：候选位置的背景风险；
- `background_update_age`：先验距最近训练期背景的时间。

经验背景图是固定站点先验，必须有版本、拟合时间范围和回退策略。它不能直接跨场地复制。

### 4.3 动态场景层

由连续背景和场景日志提供：

- 临时车辆、人员、机械或施工变化；
- 树木/旗帜等柔性物体的风致运动提示；
- 当前天气下的背景峰变化；
- 背景数据质量、丢帧、饱和和异常段。

动态场景特征只能使用当前时刻以前已确认的数据；完整扫描统计只能作为离线上限诊断。

## 5. 影响因子验证路线

### 阶段 F0：字段和质量审计

先不训练模型，检查：

- 气象时间戳与雷达事件是否能对齐；
- 变量单位、范围、缺失和传感器质量是否合理；
- site/azimuth/range 是否有足够重复背景；
- 目标和背景是否在相同配置下存在；
- 条件是否与日期、目标类别或 session 完全绑定。

输出：条件覆盖表、缺失图、混杂矩阵和“可用/不可用变量”清单。

### 阶段 F1：不加环境变量的分层基线

冻结信号模型 `S0`，只按天气和场地分组报告：

- `Pfa`、`Pd`、`Joint Pd`；
- 距离/速度/角度误差；
- 最差条件组与组间差异；
- 置信区间按 session/event bootstrap。

这个阶段回答“环境条件下模型表现是否不同”，不回答“加入环境变量是否改善”。

### 阶段 F2：可解释统计模型

对事件级检测结果使用分层逻辑模型或广义加性模型：

```text
logit(Pd_event) = beta0 + betaW * W
                 + betaG * G
                 + betaT * target_state
                 + betaC * config
                 + u_session + u_site
```

对背景虚警使用同样结构但以背景事件/扫描为单位：

```text
logit(Pfa_event) = alpha0 + alphaW * W
                  + alphaG * G
                  + alphaC * config
                  + v_session + v_site
```

若样本不足，先使用分箱、配对差值和置换检验，不强行拟合复杂模型。统计模型输出的是关联强度和不确定性，只有在实验设计支持时才讨论因果。

### 阶段 F3：环境条件增量模型

比较以下冻结/预登记模型：

| 模型 | 输入 | 目的 |
|---|---|---|
| S0 | IQ/Power2/RD | 信号主干基线 |
| S1 | 仅气象变量 | 检查天气是否有独立可预测信息，也检查泄漏 |
| S2 | 仅场地先验 | 检查背景图是否记住站点 |
| S3 | S0 + 气象 | 测量快变条件增量 |
| S4 | S0 + 场地先验 | 测量慢变场景增量 |
| S5 | S0 + 气象 + 场地 | 评估联合输入，但必须保留回退路径 |

环境分支先采用后融合/分数校准：

```text
signal_score = detector(IQ/RD)
context = weather_features + scene_prior
final_score = calibrator(signal_score, context)
```

这样可以先观察环境变量是否只影响阈值/虚警，而不是让小样本环境分支直接改写目标定位。

### 阶段 F4：外层条件验证

至少采用一种外层留出：

- leave-one-date-out；
- leave-one-site-out；
- 留出一种未见天气条件；
- 新日期+新场地的 locked test。

环境变量的归一化、背景图和阈值只能由训练/验证组拟合。测试期不能更新场地先验后再报告同一测试结果。

## 6. 需要重点防止的误判

| 风险 | 典型表现 | 处理方式 |
|---|---|---|
| 日期混杂 | 气球只在下午，背景只在上午 | 同日期/相近时段目标-背景配对；按日期外层分组 |
| 场地记忆 | 场地先验模型在原站点很好，换站点失效 | leave-one-site-out；提供无先验回退 |
| 未来泄漏 | 用完整扫描或测试期背景更新阈值 | 只使用过去/训练期背景；完整扫描只作上限 |
| 目标被环境变量替代 | 仅天气/场地模型已经接近信号模型 | 检查条件与标签是否绑定；拒绝把捷径当物理特征 |
| 传感器不同步 | 天气变化与雷达事件对不上 | 记录时钟映射、同步误差和最近有效观测年龄 |
| 多重比较 | 试很多天气分箱只报最好的一组 | 预登记分箱和主要指标，报告全部主要比较 |
| 窗口虚增样本量 | 一个 session 切出很多窗口，区间很窄 | session/event 级 bootstrap 和分组切分 |

## 7. 评价和放行标准

环境模型只有在以下条件都满足时才考虑进入论文主结果：

1. 目标和背景在关键日期/场地/配置下有配对记录；
2. 气象和场地字段完整、可追溯、时间对齐；
3. S0 基线和环境增量模型使用同一外层分组、训练预算和阈值规则；
4. 报告 `Pfa`、`Pd`、`Joint Pd`、定位误差、最差组和计算资源，而不只报告 AUC；
5. 环境分支不能通过未来信息制造新高分，也不能损害目标保护；
6. 至少有新日期或新场地 locked test，且测试结果没有用于再选变量或阈值。

建议的论文表述顺序：先写“环境条件下的分层差异”，再写“环境先验的增量效果”，最后才讨论“固定站点部署价值”。

## 8. 当前可以立即做的工作

不等待正式外场数据，也可以先完成：

- 固定 `environment_context_observation_schema_v1.json` 字段、单位和缺失规则；
- 用学姐数据只练习 RSTM 文件与背景产品的字段挂接，不把文件名时间当真实同步时间；
- 准备天气/场地条件覆盖表和混杂矩阵脚本；
- 准备 S0--S5 的实验配置和结果表模板；
- 设计现场日志、气象仪器记录、照片/地图编号和备份哈希流程。

当前不能做：

- 用学姐数据训练正式环境模型；
- 把学姐数据的“气球 vs 其他目标”结果写成项目气象/场地泛化结果；
- 在没有真实顺序时训练 `past-only` 历史模型；
- 把 DEM/遥感图直接解释成雷达回波强度；
- 用环境变量替代目标/背景真值。
