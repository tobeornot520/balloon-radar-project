# 复杂气象、场地环境与干扰方向项目设计报告

版本：V1.0  
日期：2026-09-18  
用途：2026-09-19 组内介绍、方向讨论和后续向导师确认实验条件  
文件性质：研究设计草案，不代表设备能力、采集排期或正式实验已获批准

## 一、一页结论

环境方向值得做，但不应一开始就训练“天气识别网络”或建立完整电磁仿真。对当前项目最有价值的设计是三层结构：

```text
快变环境响应
风、阵风、降水、能见度、短时背景和系统状态
    -> 分层评价、质量判断、因果背景校准

慢变场地先验
建筑、树木、地面、遮挡、固定反射体、雷达位置与朝向
    -> 场地档案、经验背景风险图、固定部署适配

干扰与故障压力测试
RFI、饱和、丢帧、时钟重置、配置变化
    -> 干扰目录、检测/报警、可控恢复和安全降级
```

近期目标不是证明“模型适用于所有天气和场地”，而是建立一条可检验路线：

> 在同日期、同场地、同配置的目标/背景对照下，先判断环境是否解释虚警、漏检和定位失败；再检验仅使用在线可得信息的轻量校准与场地先验，能否以可接受的计算代价降低最差环境组 Pfa，同时保护 Joint Pd 和定位。

环境方向在项目总路线中的位置是：

```text
冻结 Power2/RD 单域基线
  -> 证明多域融合是否有可归因收益
  -> 量化天气/场地对性能的影响
  -> 加入轻量环境校准和固定场地先验
  -> 验证 past-only 与本地实时性
  -> 新日期/新场地 locked evaluation
```

也就是说，环境模块服务于“多域模型的泛用性和部署可靠性”，不能替代多域融合主线，也不能在基线未冻结时同时改变输入、网络、阈值和场地规则。

## 二、为什么当前项目需要这一方向

### 2.1 当前问题

现有内部开发证据表明，背景虚警和目标定位失败不是同一个问题：

- 某些虚警集中在少数 fold/背景组，提示背景异质性需要单独解释；
- BC-DPG 类校准可以改变候选分数，但不能把错误峰移动到真实位置；
- 当前六折中目标与背景日期可能混杂，不能排除模型利用日期或采集条件差异；
- complete-scan 使用整次扫描上下文，只能视为离线上界；
- 新外场数据若不记录真实时间、场地、天气和配置，后续无法研究因果历史或泛化。

因此，环境方向首先承担的是“找出性能何时失效、为什么失效、怎样形成公平对照”，其次才是增加新模型。

### 2.2 文献给出的共同启发

文献并没有提供一个可直接搬来的统一网络，但给出了稳定的方法顺序：

1. 用 CFAR/滑窗统计建立简单检测基线；
2. 将背景分成不同统计状态，避免用单一阈值解释所有场景；
3. 利用重复纯背景和场地几何建立长期先验；
4. 真实确认干扰形态后，再选择插值、AR、稀疏/低秩或深度恢复；
5. 所有去杂波/去干扰方法都必须回到下游检测、定位和目标保护评价。

逐篇依据见 [复杂气象、场地杂波与雷达干扰知识储备](ENVIRONMENT_INTERFERENCE_KNOWLEDGE_BASE_ZH.md)。

## 三、研究问题与可证伪假设

### R1：环境变量是否解释检测失败

**假设 H1。** 风速、阵风、降水、场地背景强度或系统状态变化，与背景 Pfa、目标漏检或定位误差中的至少一项存在可重复的组间差异。

**否定结果同样有价值。** 若在同步、同条件对照和足够 session 下未发现稳定差异，应保留环境变量用于报告和质量控制，不强行接入模型。

### R2：快变环境能否帮助因果校准

**假设 H2。** 在只使用当前与过去信息时，背景历史摘要和少量环境变量能降低最差环境组 Pfa，并在预登记容差内保护 Joint Pd。

**关键限制。** 没有真实逐样本时间戳、硬件序号和丢帧记录时，只能做离线敏感性分析，不能称为实时或因果模型。

### R3：固定场地先验能否帮助部署

**假设 H3。** 多日期纯背景形成的经验风险图能够识别可重复的高风险位置，并在同场地新日期上改善虚警控制。

**必须同时检查。** 收益在新场地是否消失；若消失，应将其定位为固定部署适配模块，而非跨场地泛化。

### R4：干扰压力测试能否暴露系统边界

**假设 H4。** 按真实或可控干扰统计建立的压力测试，能够稳定重现至少一种检测失败，并使简单报警/恢复基线得到可测量收益。

**关键限制。** 未经真实观测锚定的合成干扰只能用于软件压力测试，不能证明现场抗干扰能力。

### R5：收益是否值得计算代价

**假设 H5。** 环境模块相对冻结基线带来的 Pfa/最差组改善，能够在本地设备的延迟、吞吐、内存和丢帧预算内实现。

这里的“优越性”不能只看精度差值，还要同时报告新增参数、运算量、P50/P95/P99 延迟、持续运行和能耗/资源占用。

## 四、总体设计

### 4.1 系统信息流

```text
原始 IQ / Power2 / RD --------------------> 冻结基础检测器
       |                                          |
       |                                          v
       +--> 当前及历史背景摘要 ----------> 候选分数/阈值校准
       |                              ^           |
       +--> 气象与系统状态 ------------|           v
       |                              |     检测 + 定位结果
       +--> 历史纯背景场地风险图 -------+           |
       |                                          v
       +--> 干扰/故障质量门 ----------------> 报警、拒收或降级
```

基础检测器负责目标候选和位置；环境模块优先只做分层、质量判断或候选分数校准。这样可以单独回答“环境信息是否有增益”，也能避免场地模块随意移动目标峰。

### 4.2 建议的轻量校准接口

对时间 `t` 的候选，定义：

- `s_t`：冻结基础模型候选分数；
- `b_t`：仅由过去背景形成的统计摘要；
- `m_site`：由开发期纯背景形成的场地风险；
- `e_t`：当前可获得的风、雨、能见度和系统状态；
- `q_t`：数据完整性和干扰质量标记。

第一版只学习或设定一个受约束的校准量：

```text
s'_t = calibrate(s_t, b_t, m_site, e_t, q_t)
```

推荐先比较单调、低参数的回归/分箱校准和非负风险惩罚，再考虑神经网络。若使用只降低分数的惩罚，必须审计它是否通过过度压低目标换取较低 Pfa；若允许提高分数，则必须额外检查是否制造新高分虚警。

场地图缺失、新场地、气象传感器失联或质量门失败时，系统必须能退回冻结基础检测器，而不是静默填入伪造值。

## 五、需要采集的数据

### 5.1 必须先向设备方确认的雷达事实

| 类别 | 必须确认 | 原因 |
|---|---|---|
| 体制与原始量 | 波形/体制、原始 IQ 含义、数据层级 | 决定 STFT、干扰模型和物理解释是否成立 |
| H/V | 通道映射、同步、相干性、幅相标定 | 决定能否使用相对相位、相关和极化术语 |
| 坐标轴 | 采样率、PRF、距离/速度/角度映射 | 决定物理轴和定位误差 |
| 时间 | UTC 或可对齐硬件时钟、单调序号、重置计数 | 决定 past-only、同步和实时回放 |
| 配置 | 增益、波束、朝向、固件、处理参数和配置 ID | 防止把配置变化当环境变化 |
| 运行状态 | 丢帧、饱和、温度、重启和错误日志 | 区分环境影响与设备故障 |

这些事实未确认前，仍可进行字段设计和软件 smoke test，但不能开始物理解释型正式实验。

### 5.2 每个 session 的必采字段

| 模块 | 最低字段 | 用途 |
|---|---|---|
| 标识与顺序 | `experiment_id`、`session_id`、`scan_id`、`frame_id`、硬件序号、UTC 时间 | 分组、因果顺序和追溯 |
| 雷达配置 | `radar_config_id`、`calibration_id`、位置、朝向、俯仰 | 固定配置和场地对齐 |
| 目标真值 | 是否有目标、对象实例、载荷状态、事件起止、距离/速度/角度或可审计代理 | 检测、定位和状态分层 |
| 背景对照 | 同日期/场地/配置的纯背景 session | Pfa 和背景风险图 |
| 气象 | 风速、风向、阵风、温湿度、气压、降水、能见度、传感器时间 | 快变环境分层 |
| 场地 | `site_id`、场地类别、照片/简图、建筑/树木/金属体、遮挡扇区 | 场地先验和解释 |
| 干扰/故障 | 干扰观察、附近发射设备、饱和、丢帧、重启、异常操作 | 质量门和压力测试 |
| 实时资源 | 推理开始/结束、队列、内存、CPU/GPU、丢帧 | 本地部署评价 |

文件名时间、MAT header 时间和文件系统 mtime 不得代替真实采集时间。

### 5.3 仪器分级

**必需或优先借用：** 雷达与原始数据导出设备、同步视频、可记录时间的目标真值设备、带时间戳的风速风向/阵风测量、温湿度气压记录、统一时间/同步工具。

**条件允许时增加：** 降水和能见度传感器、RTK/GNSS、测距/测角设备、场地测绘工具、独立频谱观察设备和本地推理计算设备。

**暂不作为前置条件：** 风廓线雷达、雨滴谱仪、高精度 CFD、全波电磁仿真和完整遥感反演。它们成本高，且在基础数据合同未通过时不会解决混杂问题。

## 六、分阶段实验设计

### 6.1 E0：事实确认与 Dry Run

目标是确认数据能被正确读取、同步、回放和追溯，不训练环境模型。

至少验证：

- H/V 文件变量、形状、复数性和有限值；
- 雷达、视频、真值和气象时间映射；
- session 开始/结束、重启、丢帧和配置变更可记录；
- 纯背景、目标进入和目标离开事件可在多源记录中对应；
- 数据可通过 `sample -> event -> scan -> session -> experiment` 回溯。

### 6.2 E1：最小 Pilot

Pilot 的任务是发现链路和标签问题，不用于最终性能宣称。建议同一天、同一场地、同一雷达配置下至少覆盖：

| 场景 | 内容 | 建议独立 session | 核心对照 |
|---|---|---:|---|
| P0 | 纯背景 | 3 | 覆盖目标前后相近时段 |
| P1 | 无载球或基础目标 | 3 | 对应 P0 |
| P2 | 同一目标有载/稳定 | 3 | 对应 P0，尽量与 P1 配对 |
| P3 | 同一目标自然摆动/旋转 | 3 | 对应 P0，记录状态起止 |
| P4 | 冷启动、历史不足和重启回放 | 1 组以上 | 检查 past-only 状态机 |

实际数量须根据设备吞吐、场地时间和导师意见冻结。上述数字是最小链路检查建议，不是统计功效结论。

若 Pilot 当天自然出现不同风况，应连续记录并作为探索分层；不要为了凑“恶劣天气”在不安全条件下作业。

### 6.3 E2：扩展采集

Pilot 通过后分批扩展，而不是试图一次采完：

1. **同场地跨日期。** 重复目标与背景配对，验证场地风险图稳定性；
2. **同场地不同环境。** 覆盖可安全获得的风、雨和能见度范围；
3. **跨场地。** 至少增加一个几何结构不同的场地，检查场地先验失效与降级；
4. **跨对象/状态。** 在真值能力允许时增加对象实例、载荷和运动状态；
5. **连续运行。** 每种候选部署配置建议持续回放或运行不少于 600 s，记录延迟和丢帧。

每轮采集后先做质量审计，再根据缺口安排下一轮。多轮采集可以减少单次失误，也能逐步建立日期和环境多样性。

### 6.4 E3：干扰与故障压力测试

先从不会产生额外射频风险的软件/数据级测试开始：丢帧、短时缺失、时间戳异常、噪声底变化、局部饱和和受控合成污染。

主动射频发射、频谱占用或现场干扰注入必须由导师、设备方和场地方确认合法、安全且不会影响其他系统；未经授权不做。

### 6.5 E4：锁定评价

在特征、模型、阈值、校准规则、场地初始化、缺失处理和指标全部冻结后，使用未参与设计的新日期或新场地目标/背景数据只评价一次。

开发、验证和 locked test 必须按 session/日期/场地等外层单位隔离，不能随机切窗后把同一连续记录分到不同集合。

## 七、算法比较矩阵

| 编号 | 方案 | 目的 | 当前优先级 |
|---|---|---|---|
| B0 | 冻结 Power2/RD 单域基线 | 所有比较的参照，保留可归因性 | 必做 |
| B1 | 同预算多域融合模型 | 证明多域收益是否超过复杂度代价 | 项目主线，必做 |
| E0 | 只分层、不把环境送入模型 | 判断环境是否真的影响失败 | 环境方向第一步 |
| E1 | CFAR/局部背景统计 | 简单环境自适应基线 | 必做 |
| E2 | past-only 背景校准 | 检验历史上下文的因果价值 | 时间合同通过后 |
| S1 | 经验场地风险图 | 固定部署场地适配 | 多日期纯背景后 |
| E3 | 环境变量轻量校准 | 检验气象元数据增量价值 | E0 有稳定信号后 |
| I1 | 干扰质量门/报警 | 先识别不可用输入并安全降级 | 有真实异常后 |
| I2 | AR/插值/稀疏或低秩恢复 | 比较可解释恢复基线 | 干扰形态确认后 |
| I3 | CNN/Transformer 恢复 | 复杂方法上限 | 数据和简单基线充分后 |

公平比较要求同一 split、同一目标/背景数据、同一阈值选择规则和可比训练预算。若同时改变输入域、模型大小、后处理和阈值，结果不能归因于环境信息。

## 八、评价与验收门

### 8.1 主要指标

- `Pfa`：背景样本中过冻结阈值的比例；
- `Score Pd`：目标样本中过阈值的比例；
- `Joint Pd`：目标样本中检测且定位满足容差的比例；
- 定位误差：无条件和条件范围分别报告 MAE、中位数、P90/P95/P99 和最大值；
- 分组结果：pooled、macro、每日期/场地/天气、worst group；
- 目标安全：目标分数变化、峰移动、新增/删除检测和大位移失败；
- 实时性：P50/P95/P99 延迟、吞吐、内存、队列、丢帧和持续运行；
- 复杂度：参数量、计算量和新增传感器/标注成本。

样本级区间不能代替 session 级不确定性。背景 session 少时，要明确说明区间不稳定，bootstrap 不能创造不存在的环境多样性。

### 8.2 进入下一阶段的门

| 阶段 | 放行条件 | 不通过时的处理 |
|---|---|---|
| 数据放行 | 同步、顺序、配置、目标真值和背景对照可审计 | 只作 capture/接口调试 |
| 环境分层 | 每个主环境组有独立目标和背景 session | 合并为连续变量或只作描述 |
| 校准放行 | 验证集上 Pfa 改善且目标保护满足预登记容差 | 保留为负结果，不进 locked test |
| 场地先验 | 同场地跨日期可重复，换场地能识别并降级 | 仅作场地诊断图 |
| 干扰恢复 | 真实形态可复现，简单基线和干净参考可信 | 只保留压力测试 |
| 实时放行 | past-only 语义、冷启动、重启、丢帧和资源预算通过 | 仍称离线算法 |
| 论文放行 | locked test 一次评价、版本和证据可追溯 | 只报告内部开发证据 |

具体 Joint Pd 非劣容差和延迟预算应在 Pilot 后、locked test 前由团队与导师预登记，不能根据测试结果倒推。

## 九、混杂、泄漏与失败模式控制

### 9.1 必须避免的混杂

- 目标只在晴天、背景只在雨天；
- 目标和背景来自不同日期或不同雷达配置；
- 某个场地只出现某一类别；
- 同一 session 切成窗口后随机跨训练和测试；
- 用测试集选择气象分箱、历史窗口或场地图阈值；
- 把文件 mtime 当采集顺序；
- 用未来样本构成所谓实时背景；
- 用模拟干扰训练和测试，却写成真实现场抗干扰。

### 9.2 环境模块可能造成的新风险

| 风险 | 表现 | 控制 |
|---|---|---|
| 场地记忆 | 原场地很好，新场地失败 | site/date 外层留出，场地未知时降级 |
| 天气捷径 | 模型用天气猜类别 | 同条件目标/背景，元数据消融 |
| 目标过抑制 | Pfa 降低但 Score/Joint Pd 下降 | 配对目标安全审计 |
| 错误恢复 | 图像变干净但目标峰移动 | 下游定位和峰移动审计 |
| 非因果上下文 | 离线好但上线不可实现 | 严格 past-only 回放 |
| 传感器缺失 | 环境输入中断导致异常输出 | 缺失显式标记与冻结基线回退 |

## 十、实施阶段与交付物

## 十二、明天组会可直接使用的 12 分钟提纲

### 0--1 分钟：先讲结论

“我负责复杂气象和环境方向。我的初步结论是把它拆成快变环境、慢变场地和干扰压力测试三层。近期先记录和分层，不立即训练天气分类网络。”

### 1--3 分钟：说明为什么要做

- 当前虚警集中在少数背景组，但原因还没有物理标签；
- 现有日期/场地可能混杂，不能直接声称泛化；
- 新数据如果没有时间、天气和场地记录，后续实时和环境研究都无法开展。

### 3--5 分钟：讲三层设计

- 快变：风雨、能见度和短时背景，用于分层和因果校准；
- 慢变：固定建筑、树木、遮挡和长期背景，用于场地风险图；
- 异常：RFI、饱和、丢帧和时钟问题，用于质量门和压力测试。

### 5--7 分钟：讲实验怎么采

- 每个重要日期/场地/配置都尽量同时采目标和纯背景；
- 记录真实时间、硬件序号、配置、视频/真值和连续气象；
- 先 Dry Run 和小 Pilot，再跨日期、天气和场地分批扩展；
- 场地照片、雷达朝向和强反射体与信号同样重要。

### 7--9 分钟：讲算法顺序

“先保留 Power2/RD 和多域融合主线；环境侧先做分层、CFAR、past-only 校准和经验背景图。只有确认真实干扰后，才比较重建和深度网络。”

### 9--10 分钟：讲怎样判断有效

“不能只看 AUC 或图片变干净。主要看 Pfa、Score Pd、Joint Pd、定位误差、最差环境组和延迟。Pfa 下降必须同时检查有没有压低目标。”

### 10--12 分钟：请团队决定问题

把下一节中的问题逐项确认，形成责任人和截止时间；不能当场确认的标记为“向导师/设备方询问”。

## 十三、组会需要形成的决定

1. 合作雷达能否导出逐帧/逐脉冲时间、硬件序号、原始 IQ、完整配置和运行日志？
2. H/V 的物理含义、同步和标定能由谁提供证据？
3. 外场可借用哪些气象、视频、RTK/测距和同步设备？
4. 第一轮 Pilot 的场地、可用日期、人员和安全边界是什么？
5. 目标对象第一阶段只做空飘球检测，还是同时采无载/有载和运动状态？
6. 哪些场地条件最有可能获得：开阔地、建筑邻近、树木背景或其他固定反射环境？
7. 谁负责每次采集的 manifest、配置记录、气象记录、目标真值和现场异常日志？
8. 环境模块的第一主问题是否确定为“降低最差环境组 Pfa 且保护 Joint Pd”？
9. Pilot 后由谁冻结 Joint Pd 容差、延迟预算和 locked test 范围？
10. 是否存在已知、合法且安全可观察的现场干扰源；若没有，是否同意第一阶段只做故障/合成压力测试？

## 十四、可以说与不能说

### 当前可以说

- 已形成快变环境、慢变场地和干扰压力测试三层研究框架；
- 已整理 20 篇公开全文，并提炼了可迁移方法和体制限制；
- 已明确需要同条件目标/背景、真实时间、气象、场地、配置和运行日志；

### 当前不能说

- 场地背景图能够在未知场地直接工作；
