## 0. 课程定位与使用方式

### 0.1 这份课件要解决什么问题

这不是一份脱离代码的深度学习教材，而是带着项目成员从实际仓库读懂一条可审计研究链路：

```text
H/V 复数 IQ
    -> 距离-多普勒（RD）功率表示
    -> 热图标签与坐标映射
    -> SimpleRadarFCN 基线
    -> DualBranchGated/DPG-FCN
    -> 阈值、虚警和联合定位指标
    -> 背景校准 BC-DPG
    -> 显式极化表示 Stage 3
    -> ROI 极化精修 Stage 4
    -> 统计审计、因果边界和论文交付
```

每一课都同时回答五件事：

1. 代码到底做了什么；
2. 这样设计解决了什么问题；
3. 实验能支持怎样的论文和汇报表述；
4. 哪些结论仍然受数据、标定或部署条件限制；
5. 下一步可以怎样改进和验证。

### 0.2 当前论文主线和明确边界

当前证据支持的主线是：**在现有 H/V 双通道 UAV/背景数据上，完成目标检测、距离-速度定位和复杂背景虚警抑制的前端研究**。

当前不能写成以下结论：

- 已完成空飘球有载/无载或载荷类别识别；
- 已获得绝对校准的 `ZDR`、`PhiDP` 或其他物理极化量；
- 已证明严格实时部署性能；
- 已证明跨日期、跨场地的外部盲测泛化。

冻结数据范围为 1,148 条记录：830 条背景、318 条目标。背景只有 6 个独立扫描组，目标与背景采集日期完全耦合，因此六折结果属于**内部开发评价**，不是外部泛化证据。项目主线和边界见 [PAPER_MAINLINE_V1.md](PAPER_MAINLINE_V1.md)。

当前主方向完成门为 `4/6 BLOCKED_EXTERNAL`。H/V 物理定义、PRF/坐标和标定仍有外部阻塞；这不是代码没有运行，而是缺少足以支撑更强物理或部署声明的独立证据。

### 1.1 学习目标

完成本课后，应能回答：

- 为什么 FFT 沿慢时间做，而不是沿距离门轴做；
- Hann 窗、频谱泄漏和主瓣/旁瓣之间的关系；
- 为什么每个样本分别做 1%/99% 分位数归一化；
- 标签坐标如何变成 `[128,100]` 高斯热图。

### 1.2 代码入口

- 数据读取与几何映射：[datasets/detection_dataset_v2.py](../datasets/detection_dataset_v2.py)
- 当前 manifest 版本：[datasets/detection_dataset_v3.py](../datasets/detection_dataset_v3.py)
- 极化特征共用的复数 RD：[features/polarimetric_rd.py](../features/polarimetric_rd.py)

### 1.3 数据流

对单个 H 或 V 通道，代码执行：

```text
复数 IQ [128,100]
  -> 轴0乘 Hann 窗
  -> 沿轴0做 FFT
  -> fftshift 多普勒轴
  -> |RD|² 功率图 [128,100]
  -> 10log10(power + eps)
  -> 本图 Q1/Q99 归一化并裁剪到 [0,1]
```

核心公式为：

\[
RD(k,r)=\operatorname{fftshift}_k\{w(n)\,IQ(n,r)\},
\qquad P(k,r)=|RD(k,r)|^2.
\]

归一化为：

\[
x(k,r)=\operatorname{clip}\left(
\frac{P_{dB}(k,r)-Q_{1}}{Q_{99}-Q_{1}},0,1\right).
\]

轴 0 是脉冲序列的慢时间，脉冲间相位变化对应 Doppler；轴 1 已经是距离门。当前代码没有在轴 1 再做一次“距离 FFT”。`fftshift` 只是把 Doppler 零频移到中间，便于坐标阅读。

### 1.4 窗函数和归一化的研究含义

有限长度观测相当于用一个窗截断信号。矩形窗的频域响应可视为 sinc（离散有限情形更准确地说是 Dirichlet kernel），旁瓣较高；Hann 窗的频谱可理解为三个移位矩形窗频谱的线性组合，通过相消降低远端旁瓣，但代价是主瓣变宽、相近 Doppler 的分辨能力下降。Hann 窗不会消灭旁瓣。

1%/99% 分位数归一化主要减少极端离群值对显示和网络输入的影响。它保留的是**样本内部相对强弱**，不是跨样本可比较的绝对回波功率。因此归一化后出现的峰值高，只能说明它在该图中相对突出。

### 1.5 标签和背景

目标标签先由距离和速度映射到离散下标，再生成二维高斯：

\[
y(v,r)=\exp\left[-\frac{(r-r_0)^2}{2\sigma_r^2}
-\frac{(v-v_0)^2}{2\sigma_v^2}\right].
\]

目标样本的中心位置由标签给出；背景样本的热图全零，`target_present=0`，坐标下标保持为 `-1`。目标坐标越界必须报错，不能静默改成背景，因为“越界”和“无目标”是不同的数据质量问题。

### 1.6 论文和汇报可用表述

可以写：

> 对每个 H/V 复数 IQ 样本沿慢时间施加 Hann 窗并进行 Doppler FFT，得到经 `fftshift` 的 RD 功率图；随后在每个样本内部按 1%/99% dB 分位数进行稳健归一化，并将标注的距离-速度坐标映射为二维高斯监督热图。

不能写：

- “归一化后的数值就是绝对回波功率”；
- “Hann 窗消除了频谱旁瓣”；
- “轴 1 的 100 个距离门是由本段代码完成的距离 FFT 得到的”；
- “背景坐标越界等价于背景样本”。

### 1.7 延伸概念速览：FFT、窗函数与归一化

| 概念 | 简要理解 | 本项目中的边界 |
|---|---|---|
| DFT 与 FFT | DFT 把有限序列投影到一组离散复指数频率；FFT 是更快计算 DFT 的算法，不是另一种物理变换 | 沿慢时间得到的是离散 Doppler 频率证据，不是无需参数就直接得到速度 |
| Doppler bin | FFT 输出中的离散频率格点 | 从 bin 换成 Hz 或 m/s 还依赖 PRF、载频/波长、零频位置和符号约定 |
| 频谱泄漏 | 有限窗在时域与信号相乘，对应频域与窗频谱卷积；不正好落在 bin 上的能量会扩散到邻近格点 | 泄漏不是噪声的同义词，也不会被 Hann 完全消除 |
| 主瓣与旁瓣 | 主瓣宽度影响相近频率能否分开；旁瓣可能让强目标能量遮住邻近弱响应 | Hann 降低旁瓣但加宽主瓣，是分辨能力与泄漏抑制的取舍 |
| dB 变换 | `10log10(power)` 压缩动态范围，仍保留功率的单调次序 | dB 不是归一化；绝对标尺是否可信仍取决于接收链和标定 |
| 分位数归一化 | 用 Q1/Q99 代替极端 min/max，增强对离群点的稳健性 | 每图单独缩放后主要保留图内相对强弱，跨图绝对幅度关系不可恢复 |

更系统的采样、FFT、窗函数和不可逆信息损失说明见 [技术手册第 6 节](../PROJECT_CONTROL/TECHNICAL_HANDBOOK_ZH.md)。原始讨论保留作可选溯源：[DeepSeek 延伸记录：FFT、窗函数与归一化](https://chat.deepseek.com/share/um6hr46wyrpcwfm7b3)。

### 2.1 学习目标

理解一个不改变 RD 空间分辨率的最小检测网络，并能从代码推导输出形状、理论感受野和峰值解码方式。

### 2.2 结构

`SimpleRadarFCN` 由四个 `3x3, padding=1` 的 `ConvBlock` 和一个 `1x1` 输出卷积组成：

```text
[B,C,128,100]
  -> ConvBlock C->16
  -> ConvBlock 16->32
  -> ConvBlock 32->32
  -> ConvBlock 32->16
  -> 1x1 Conv 16->1
  -> [B,1,128,100] logits
```

每个 `ConvBlock` 是 `Conv2d + GroupNorm(4组) + SiLU`，没有 pooling 或 stride，因此空间尺寸保持不变。连续四个 `3x3` 卷积的单点理论感受野为：

\[
1+4(3-1)=9,
\]

即 `9x9`。最后的 `1x1` 卷积只混合通道，不扩大空间感受野。当前 2 通道模型静态参数量为 18,929，1 通道模型为 18,785。

### 2.3 Logit、Sigmoid 和峰值

网络输出的是未经过 Sigmoid 的 `logits`。推理时：

\[
p(v,r)=\sigma(z(v,r))=\frac{1}{1+e^{-z(v,r)}}.
\]

Sigmoid 是单调函数，因此同一样本内对 logits 或 sigmoid 图取 `argmax` 得到的位置相同。检测分数是整张热图的最大值；位置是最大值对应的 Doppler/距离下标。

### 2.4 为什么用高斯热图

单点 one-hot 标签要求预测峰精确落在一个格点上，邻近格点全部被视为同样错误；高斯热图把“真实位置附近的合理偏移”编码为连续监督，使训练目标更平滑，也更符合离散 RD 网格的定位误差现实。

当前仓库存在多个历史损失实现，不能混写：

- 当前检测基线入口 [scripts/train_detection_baseline_v2.py](../scripts/train_detection_baseline_v2.py) 使用样本级加权热图 MSE，目标样本整图权重默认为 10；
- [training/train_simple_fcn.py](../training/train_simple_fcn.py) 还保留较早的像素加权 MSE + soft Dice 实现。

写论文时必须同时报告具体训练入口和损失版本。

代码审查还要记住两点：PyTorch 默认 `collate` 可以把 `sample_id` 等字符串组织成批次列表，字符串本身不是必然的崩溃原因；V3 几何映射对越界目标会显式报错，不能把异常标签静默改成背景。当前正式训练路径已经提供内存缓存，不能把“增加缓存”误报成尚未实现的改进。

背景样本通常多于目标样本，若损失完全由大量背景样本或背景像素主导，模型可能学会保守地输出低分而牺牲目标响应。因此训练路径使用样本级或像素级加权来平衡监督；具体权重必须和训练入口一起记录，不能笼统归因于“神经网络天然受多数样本影响”。

### 2.5 延伸概念速览：数据集、感受野和网络容量

**Dataset、batch 与 epoch。** PyTorch `Dataset` 不是一堆数组的别名，而是一套“给定索引，怎样读取一个样本并构造输入、标签和元数据”的规则。`DataLoader` 再负责抽样、打乱和拼 batch；处理完全部训练样本一次称为一个 epoch。数据读取规则错误时，换更大的网络也不会自动修复标签或轴含义。

**卷积尺寸。** 一维输出长度的一般公式为：

\[
N_{out}=\left\lfloor\frac{N_{in}+2p-d(k-1)-1}{s}+1\right\rfloor,
\]

其中 `k` 是卷积核、`p` 是 padding、`s` 是 stride、`d` 是 dilation。当前 `k=3,p=1,s=1,d=1`，所以输入输出长度相同；若不 padding，`128x100` 经一次 `3x3` 卷积才会变成 `126x98`，不是 `127x99`。

**卷积核怎样学习。** 卷积核初始是一组参数。前向计算产生热图，损失衡量预测与标签的差异，反向传播计算每个核参数应怎样调整，优化器再更新它。权重共享意味着同一个局部模式检测器会滑过整张 RD 图。

| 概念 | 简要理解 | 容易混淆之处 |
|---|---|---|
| 理论感受野 | 按网络连接推导，一个输出单元最多可能接触的输入范围 | `9x9` 不代表 9 个格点都具有同等影响，也不是雷达物理分辨率 |
| 有效感受野 | 训练后真正对输出影响较大的输入区域，通常集中在理论范围中心 | 需要梯度或遮挡分析才能估计，不能只由层数精确给出 |
| 网络容量 | 模型能够表达的函数集合有多丰富 | 参数量、深度和宽度是代理；结构、激活、归一化和先验同样影响表达 |
| 欠拟合 | 连训练数据中的主要规律都没有学好 | 可能由容量不足，也可能由优化、标签、学习率或实现问题造成 |
| 过拟合 | 训练表现好而新数据表现差 | 大模型风险可能更高，但“大模型必然过拟合”并不成立 |
| GroupNorm | 在单个样本内部按通道组归一化 | 不依赖大 batch 的统计量，适合当前小批量；它不会增加传感器信息 |
| SiLU | 平滑非线性 `x*sigmoid(x)` | 激活函数改变优化和表达方式，不能脱离消融断言一定优于 ReLU/GELU |

网络容量、优化是否成功和未知数据上的泛化是三个问题。训练 loss 不下降不能单独证明容量不足，校准头也不能替主检测器创造从未学到的空间信息。更系统的机器学习基础见 [技术手册第 8 节](../PROJECT_CONTROL/TECHNICAL_HANDBOOK_ZH.md)。原始讨论保留作可选溯源：[DeepSeek 延伸记录：数据集、感受野和网络容量](https://chat.deepseek.com/share/tr2tagvs7j9zb71mxb)。

### 2.6 论文和汇报可用表述

> 我们采用无下采样的全卷积热图检测器，保持输入 RD 网格到输出热图的逐单元对应关系。四个 `3x3` 卷积块提供 `9x9` 理论感受野，`1x1` 卷积完成通道到检测 logit 的映射。

### 3.1 学习目标

理解 H/V 为什么先独立编码、再做样本级门控和特征融合，以及辅助分支如何防止融合头抛弃某一通道。

### 3.2 结构

```text
H Power RD -> 独立 SimpleRadarFCN -> H feature/logit
                                      \
                                       -> gate -> w_H, w_V
                                      /
V Power RD -> 独立 SimpleRadarFCN -> V feature/logit

weighted H, weighted V, |H-V|, H*V
              -> fusion head -> fusion logits
```

H/V 分支各自使用单通道 `SimpleRadarFCN`，因此可以分别加载已有的单通道 checkpoint。每个分支末端特征为 16 通道；门控输入为 H/V 两个 16 维全图均值描述和两个分支 peak score，共 34 维，经 `34->16->2` MLP 后做 softmax：

\[
w_H+w_V=1,
\qquad w_H,w_V\ge 0.
\]

注意门控是**样本级**的，不是每个 RD 单元一个独立权重，也不能直接解释成绝对的 H/V 物理功率贡献。

融合头接收 64 个通道：`w_H H`、`w_V V`、`|H-V|`、`H*V` 各 16 个通道。绝对差强调分支差异，共同乘积强调共同响应。

### 3.3 训练阶段与辅助损失

当前训练分三阶段：

1. `warmup`：冻结 H/V 分支，只训练门控和融合头；
2. `partial`：解冻每个分支后两个卷积块及输出头；
3. `full`：解冻两个完整分支。

总损失为：

\[
L=L_{fusion}+0.2L_H+0.2L_V.
\]

辅助损失使 H/V 分支保持独立检测能力，降低融合头完全忽略某一分支的风险。`0.2` 是当前脚本/配置的工程超参数，不是物理定律；其来源和是否应学习仍是改进项。

### 3.4 延伸概念速览：门控、辅助监督与分支退化

| 概念 | 简要理解 | 本项目中的对应 |
|---|---|---|
| MLP | 多层全连接网络，把固定长度描述映射为新的标量或向量 | gate 用 `34->16->2` MLP 预测每个样本的 H/V 相对权重 |
| 门控 | 根据当前输入动态调节不同分支的贡献，属于条件混合 | 当前 gate 每个样本输出一对权重，不是每个 RD 单元的空间注意力图 |
| softmax 竞争 | 权重非负且和为 1；提高一支的相对权重会压低另一支 | 它约束相对选择，但不证明权重就是 H/V 物理能量占比 |
| 分支专门化 | H/V 分支分别学习各自的局部响应和噪声模式 | 独立编码允许加载单通道 checkpoint，也保留通道差异 |
| 分支退化/塌缩 | 融合头长期忽略某一支，使该分支不再具备独立可用的检测表示 | 当 gate 或融合层总偏向一支时可能发生，需要看分支输出和权重分布审计 |
| 辅助监督 | 除最终融合损失外，直接给中间分支增加训练目标，使梯度能到达各分支 | `0.2L_H+0.2L_V` 鼓励 H/V 各自维持检测能力，但不能数学保证永不退化 |

`|H-V|` 和 `H*V` 分别给融合头提供“分支差异”和“共同高响应”的学习特征；它们作用在网络特征图上，不是原始复数 IQ 的极化互相关或散射矩阵元素。辅助损失权重也可以设计为可学习量，但若没有约束，模型可能通过把困难分支权重降得很低来获得较小总损失，反而削弱保留分支能力的初衷。

更系统的 DPG 结构说明见 [技术手册第 9.3 节](../PROJECT_CONTROL/TECHNICAL_HANDBOOK_ZH.md)。原始讨论保留作可选溯源：[DeepSeek 延伸记录：门控、辅助损失与分支退化](https://chat.deepseek.com/share/ixe8ewz8fs07uu0vz8)。

### 3.5 论文和汇报可用表述

### 4.1 三种数据角色

```text
train：更新模型参数
val：选择 checkpoint、阈值和开发期超参数
test：使用已冻结模型和阈值做最终评价
```

测试集一旦被用于挑阈值、挑模型或挑融合规则，就不再是独立的最终评价。当前六折结果仍应称内部开发评价。

### 4.2 阈值选择

验证集上先固定背景虚警预算 `B`，遍历候选分数阈值，保留背景虚警数不超过 `B` 的阈值集合，再选择其中最低的可行阈值，以尽量保留目标。

这是一个约束优化问题：

\[
\min_t\ t
\quad\text{s.t.}\quad FA_{val}(t)\le B.
\]

当前脚本的判定实现是 `score > threshold`；自然语言文档曾写“不低于”，论文和代码应统一这一等值边界（见 `IMP-25`）。

### 4.3 指标必须分开

| 指标 | 定义 | 是否要求定位正确 |
|---|---|---|
| Score Pd | 目标样本分数超过阈值的比例 | 否 |
| Joint Pd | 目标样本同时过阈且距离/速度在容差内的比例 | 是 |
| Pfa | 背景样本分数超过阈值的比例 | 不适用 |
| AUC | 目标与背景分数排序能力 | 否，不含定位 |

因此对同一个输出总有 `Joint Pd <= Score Pd`。AUC 可评价排序，但不能代替项目最终关心的检测-定位联合成功。

特别禁止把 `Score Pd` 叫作“单通道 Pd”，把 `Joint Pd` 叫作“融合 Pd”。二者可以同时针对 fusion 输出：前者只检查过阈，后者还检查定位。

### 4.4 checkpoint 选择

DPG 当前优先级是验证集 `Joint Pd`，再比较较低 `Pfa`、AUC 和损失。BC-DPG v3 另有安全资格门：校准验证 `Joint Pd` 不得比 raw 低超过 0.01，只有合格 checkpoint 才优先比较更低的 Pfa。

样本级 Pfa 不能换算成“每小时虚警率”，因为当前数据没有统一观测时长和事件合并定义。

### 4.5 延伸概念速览：工作点、ROC/AUC 与模型选择

`Pd` 是 probability of detection 的传统记号，`Pfa` 是 probability of false alarm 的传统记号；当前表中的数值是有限样本上的经验比例。这里的一个“背景试验”是一条背景记录是否报警，不是一个 RD cell，也不是一小时观测。

| 概念 | 回答的问题 | 是否依赖固定阈值 | 是否检查定位 |
|---|---|---:|---:|
| Score Pd | 目标峰值是否超过当前工作阈值 | 是 | 否 |
| Joint Pd | 目标是否过阈，而且预测坐标是否在容差内 | 是 | 是 |
| Pfa | 背景记录是否在当前阈值产生报警 | 是 | 不适用 |
| ROC | 阈值从高到低变化时，TPR 与 FPR 怎样权衡 | 扫描多个阈值 | 否 |
| AUC | 随机目标分数高于随机背景分数的总体排序能力 | 不对应单一阈值 | 否 |
| pAUC / TPR@FPR | 低虚警局部区域的排序或召回能力 | 看一段或一个约束区间 | 否 |

Joint Pd 是“过阈目标集合”与“定位正确集合”的交集，所以不会大于 Score Pd。AUC 高说明总体排序较好，却不保证冻结部署阈值处的 Pfa 或 Joint Pd 更好；雷达低虚警任务还应查看预先规定的低 FPR 区间。

还要区分三个选择步骤：网络结构/损失属于方法选择，checkpoint 属于训练时刻选择，阈值属于工作点选择。它们都应只使用允许的 train/validation 信息。若查看很多 checkpoint、指标和阈值后只报告最漂亮的一项，就形成隐性多重比较和乐观偏差。

更系统的阈值、ROC 与指标定义见 [技术手册第 10-11 节](../PROJECT_CONTROL/TECHNICAL_HANDBOOK_ZH.md)。原始讨论保留作可选溯源：[DeepSeek 延伸记录：Score Pd、Joint Pd、AUC 和模型选择](https://chat.deepseek.com/share/kmu3n3ksjlj1ncengx)。最重要的术语纠正仍是：Score/Joint Pd 是同一输出的两种成功口径，不是“单通道 Pd”和“融合 Pd”。

### 5.1 为什么需要背景校准

不同扫描的底噪、杂波和背景峰分布可能不同。同一 raw 分数在不同扫描条件下不一定具有相同的虚警风险。BC 的作用是利用当前样本或扫描上下文，调整候选分数的可信度和背景抑制强度。

### 5.2 旧版：样本条件温度/偏置校准

`BackgroundCalibratedDPGFCN` 冻结 DPG 基础模型，用 12 维当前样本统计经过 MLP 预测每个样本自己的 `T>0` 和 `b`：

\[
z_{cal}(x)=\frac{z_{raw}-b(x)}{T(x)}.
\]

12 维特征包括 H/V 均值、标准差、最大值、top-k 均值，两个 gate 权重，以及 raw 热图 peak/top-k 统计。`b` 不是全局标量，也不是直接在验证集上逐样本优化出来的；MLP 参数由训练集学习，验证集选择 checkpoint 和阈值。

由于旧版允许 `b` 正负、`T` 大小变化，它保持样本内排序和 argmax，但不保证每个分数只下降。因此不能把旧版称为 suppression-only。

### 5.3 当前主线：target-protected scan-aware BC-DPG v3

当前 v3 的训练入口先使用冻结的 DPG/背景特征提取器构造 24 维 sample features，再把它与 12 维 scan context 和 raw peak logit 一起输入可训练的 `TargetProtectedScanCalibrator`。当前真正训练的是目标保护校准头，而不是重新训练整张 DPG-FCN。

当前 v3 预测：

- `p_background`：当前候选是背景峰的模型分数；
- 有界的 `suppression`：最大抑制量。

\[
shift=p_{background}\cdot suppression\ge 0,
\qquad z_{cal}=z_{raw}-shift.
\]

校准头在候选层面产生一个空间统一的 `shift`，再从冻结 DPG 的候选 raw logit 中扣除；因此分数不会增加，原始 DPG 的距离-速度 `argmax` 被保留。它不能救回 raw 分数很低的漏检，只能压低背景候选。

v3 的损失同时包含背景分类、背景尾部、目标保留、成对排序、抑制选择性和正则项。配置中的资格门是：

\[
JointPd_{BC,val}\ge JointPd_{raw,val}-0.01.
\]

先守住目标能力，再比较虚警下降，避免“把所有分数压成零”这种伪改进。

### 5.4 扫描上下文与实时边界

- `complete-scan`：使用整组扫描统计，可能包含未来样本，是离线扫描感知上限；
- `leave-one-out`：排除当前样本，但仍可能使用未来样本；
- `past-only`：只使用假定顺序中的历史样本；当前顺序没有经过真实时间戳验证，且完整模型未按该分布重新训练。

冻结内部数字可作为方法证据，但不能写成实时性能：样本独立 BC 为 122/830 背景虚警、289/318 联合成功；完整扫描 v3 为 56/830、289/318。完整 v3 的 56 个虚警全部集中在 Fold 1 和 Fold 4。

### 5.5 延伸概念速览：单调变换、排序范围与概率校准

对某一个样本，旧版的 `T(x)>0` 和 `b(x)` 对整张热图所有位置相同。若两个位置有 `z_1>z_2`，则：

\[
\frac{z_1-b(x)}{T(x)}>\frac{z_2-b(x)}{T(x)}.
\]

所以该样本内部的空间排序和 argmax 不变；后接的 sigmoid 也是严格单调函数，同样不改变峰位置。但不同样本拥有不同的 `T(x),b(x)`，因此样本 A 与样本 B 的峰值先后关系可以改变。“排序不变”必须明确是**单张热图内部**，不能扩大成整个数据集排序不变。

| 概念 | 作用 | 不能推出什么 |
|---|---|---|
| 温度 `T` | `T>1` 通常压缩 logit 差异，`0<T<1` 放大差异 | 不是物理温度，也不自动提高分类能力 |
| 偏置 `b` | 移动该样本 logit 的共同基准，改变是否跨过固定阈值 | 不是人工逐样本调出来的常数；当前由 MLP 根据样本统计学习 |
| v3 suppression | 从 raw peak logit 中减去非负量，结构上保证分数不增加 | 不能召回低分目标，也不能改善候选坐标 |
| confidence / score | 模型用于排序和阈值判决的数值 | `0.9` 不自动等于现实中 90% 的正确概率 |
| probability calibration | 在大量相似预测中，声称为 0.9 的事件约有 90% 发生 | 需要独立数据上的可靠性图、ECE、Brier score 等诊断 |

旧版 `T,b` 更接近温度/偏置式分数变换；v3 的主要目标是带安全约束的背景抑制。二者都可能利用当前数据中的日期、增益或背景捷径，所以“分数更可信”仍须限定在评价数据和指标范围内。

更系统的背景校准和概率术语见 [技术手册第 8.6、9.4 和 11 节](../PROJECT_CONTROL/TECHNICAL_HANDBOOK_ZH.md)。原始讨论保留作可选溯源：[DeepSeek 延伸记录：排序不变、可信度与偏置来源](https://chat.deepseek.com/share/itd0lo20y458nwflck)。

### 6.1 Power2 的双重地位

Power2 不是“因为简单所以天然最好”。它有两个研究角色：

### 6.3 为什么固定网络容量

### 7.1 为什么从全图表示转向候选精修

Stage 3 说明复杂极化表示直接承担全图检测和定位时没有稳定超过 Power2。Stage 4 因此冻结 Power2 的候选峰、距离/速度坐标、原始分数和部署阈值，只在候选附近回答一个更窄的问题：这个候选需要被压低多少？

```text
H/V IQ -> Power2 全图候选 -> 冻结坐标与原分数
       -> 截取 11x9 ROI -> 局部精修器 -> 只降低候选分数
```

这个设计把全局定位和局部确认分开。ROI 网络不能重新搜索全图峰，也不能修复 Power2 的错误坐标。

### 7.2 ROI 特征、边界和控制组

共享全图特征源为 `[10,128,100]`：H/V Power2 两通道、H/V 复数 RD 的 RI4 四通道，以及门控 `zdr_like`、局部 `rho_HV`、相对相位 `cos/sin` 四通道。默认 Doppler 半径为 5、距离半径为 4，所以 ROI 是 `11x9`。

边界外位置补零，同时用 `[1,11,9]` 的 `valid_mask` 标记真实像素为 1、人工补零为 0；Doppler 轴不循环拼接。若没有 mask，网络无法区分“传感器中真实的低响应零值”和“越界后人工补出的零值”。当前网络只把 mask 化为 `valid_fraction` 标量，告诉精修器 ROI 中有多少比例来自真实图像；这种做法保留了有效面积，却丢失了无效位置的空间分布，后续可与显式 mask 通道做消融。

| 模式 | 活跃信息 | 实验角色 |
|---|---|---|
| `power2_roi_power_control` | H/V Power2 | 测量 ROI 机制本身的收益 |
| `power2_roi_ri4` | H/V 实部和虚部 | 测量 RI4 相对控制组的增量 |
| `power2_roi_polar6_gated` | Power2 + 四个门控相对极化量 | 检验显式极化量 |
| `power2_roi_ri4_polar6_gated` | RI4 + 四个门控相对极化量 | 检验两类表示的互补性 |

四种输入统一补成 8 通道。若没有 `power control`，Power2 与 ROI RI4 的差异会同时包含局部 ROI 机制和 RI4 信息，无法归因。

### 7.3 suppression-only 精修器

ROI 编码器执行 `8->16->32->AdaptiveAvgPool(1)`，再拼接 raw logit、raw score、valid fraction 和 polarimetric confidence。输出非负抑制量：

`AdaptiveAvgPool(1)` 会把每个通道的整张 ROI 特征图汇聚为一个数，因此 32 个输出通道变成 32 维局部描述。它让后续全连接层接收固定长度输入，但汇聚后不再保留“响应位于 ROI 左上还是右下”这类精细位置关系。

```text
suppression >= 0
refined_logit = raw_logit - suppression
refined_score = sigmoid(refined_logit)
```

因此 `refined_score <= raw_score`。沿用同一固定阈值时，原本未报警的背景不能被提升成新虚警；但原本刚过阈值的目标可能被压到阈值以下。抑制头 bias 初始化为 `-6`，使训练初态接近 Power2 恒等映射，而不是立即压低所有候选。

### 7.4 损失和 checkpoint 资格门

训练损失包括 refined detection BCE、名为 `roi_quality` 的目标/背景辅助分类 BCE、background-tail、target-protection 和 suppression 平方正则。默认主要权重依次为 quality `0.2`、background tail `1.0`、target protection `2.0`、shift regularization `0.01`。

| 损失或指标 | 直观作用 | 当前代码中的含义 |
|---|---|---|
| BCE | 二元交叉熵，惩罚二分类预测与 0/1 标签不一致 | detection BCE 监督精修后的候选 logit；quality BCE 让辅助头预测 `target_present` |
| background-tail | 重点处理最可能越过阈值的高分背景尾部 | 背景 refined logit 越接近或超过带 margin 的部署阈值，惩罚越大 |
| target-protection | 防止以压低真实目标换取更少虚警 | 对目标候选的平均 suppression 直接施加代价 |
| shift regularization | 限制不必要的过大抑制 | 对所有候选的 suppression 平方取平均；它是保守约束，不单独负责区分类别 |

这里的网络输出 `roi_quality` 是辅助分类分数；缓存中另有一个同名字段，表示 ROI 内 H/V 联合功率的有效区域均值。二者只是历史命名相同，不能当作同一个量。

checkpoint 必须先满足：

```text
refined validation Joint Pd >= raw validation Joint Pd - 0.01
```

合格后才依次优先选择更低 Pfa、更高 Joint Pd、更高 pAUC@5% FPR 和更低 loss。`pAUC@5% FPR` 只汇总 ROC 曲线中 `FPR<=5%` 的低虚警区域，用来观察模型在项目关心区间内的排序能力；它不是“固定阈值 Pfa 等于 5%”，也不检查定位。当前实现调用带 `max_fpr=0.05` 的标准化 partial AUC。主评价沿用冻结 Power2 阈值，不在测试集重新调阈值。

### 8.0 学习任务卡

| 项目 | 内容 |
|---|---|
| 预计时间 | 75 分钟 |
| 先修知识 | 第 4 课、平均数/中位数、交叉验证和独立样本概念 |
| 必须阅读 | `docs/DATA_CARD.md`、`docs/METRIC_DEFINITIONS.md`、`results/final_evidence/roi_bc_dpg_joint_fixed_threshold/JOINT_AUDIT_REPORT.md` |

| 不要求做什么 | 不从 bootstrap 声称新增环境多样性，不把六折称外部盲测，不重新选择 fold 或主指标 |

### 8.1 记录数不等于独立实验数

冻结数据共有 1,148 条记录，其中背景 830 条、目标 318 条；但背景只有 6 个扫描组，目标有 71 个扫描组。同一扫描中的记录共享天气、场地、雷达状态、杂波结构和相邻方位，BC-DPG 还显式使用扫描上下文，因此不能把它们视为完全独立的环境实验。

按扫描组划分可以防止同一扫描的相邻记录分别进入训练和测试造成组泄漏。它不能自动消除日期、场地或采集流程与类别之间的混杂。

### 8.2 pooled、macro 和折间异质性

pooled Pfa 按记录汇总：

```text
pooled Pfa = sum(false alarms) / sum(background records)
           = 56 / 830 = 0.0675
```

macro Pfa 先计算每折 Pfa 再等权平均：

```text
macro Pfa = mean(Pfa_fold_1, ..., Pfa_fold_6) = 0.0622
```

pooled 让记录多的折权重更大，macro 让每个折权重相同。BC-DPG 的 pooled Joint Pd 为 `289/318=0.9088`，macro Joint Pd 为 `0.9059`，两种口径不能混写。

56 个虚警全部集中在 Fold 1 的 42 个和 Fold 4 的 14 个，其他四折为零。因此 median Pfa 为零，但最差折 Pfa 为 `0.2800`。主报告需要同时给出 pooled、macro、median、worst fold 和逐折分布，不能用一个总体数掩盖困难背景。

### 8.3 样本级区间与扫描组 bootstrap

样本级 Wilson 区间把每条记录近似视作独立伯努利试验，得到 Joint Pd `0.8721-0.9358`、Pfa `0.0523-0.0866`。同一扫描内记录相关时，这种区间会显得过窄，只能作为样本级参考。

扫描组 bootstrap 以整个扫描组为重采样单位，组内记录一起进入或离开一次重采样，得到 Joint Pd `0.8599-0.9521`、Pfa `0-0.1618`。更宽的 Pfa 区间反映换一个背景环境带来的变化，但只有 6 个背景组，区间本身仍不稳定；bootstrap 不能创造原数据中没有的环境多样性。

### 8.4 日期混杂与独立盲测

当前 71 个目标扫描组全部来自 `20260202`，6 个背景扫描组全部来自 `20260204`，所以类别与采集日期完全耦合。模型观察到的差异既可能来自目标，也可能来自环境、硬件状态或采集流程。扫描组隔离不能解开这种混杂，当前不能声称跨日期泛化。

测试阈值没有重调是必要条件，但不是独立盲测的充分条件。六个 fold 均参与过项目开发，BC-DPG 设计受开发反馈影响，Stage 4 又先用 Fold 1/4 筛选模式并把它们纳入六折汇总。因此当前应称“六折分组内部开发评价”，而不是外部独立盲测。

真正的确认性评价需要先冻结模型、特征、阈值、组合规则和指标，再对从未参与设计的新日期或新场地数据只评价一次。新数据还应包含同日期目标/背景对照、多个日期和场地、真实时间戳与扫描标识。

### 8.5 论文和汇报表述

可以写：BC-DPG 在六折分组内部评价中得到 `56/830` 的背景虚警和 `289/318` 的联合成功；扫描组 bootstrap 表明背景泛化不确定性仍然较大。

不能写：模型已证明在未知日期和未知环境中具有稳定的 `6.75%` 虚警率。当前还缺少观测时长和事件合并合同，也不能把 56 个样本级虚警换算为每小时或事件级虚警率。

2. 六折 median Pfa 为 0，为什么仍不能说模型已经稳定解决了背景虚警？

### 9.1 定位合同和四象限分解

热图 argmax 给出预测距离、速度索引。目标样本的绝对误差为 `|pred_range-true_range|` 和 `|pred_velocity-true_velocity|`；距离不超过 2 gates 且速度不超过 3 bins 才算 `localization_ok`。

318 个目标中有 302 个分数过阈、297 个不考虑分数时定位正确、289 个同时满足两者：

|  | 定位正确 | 定位错误 |
|---|---:|---:|
| 分数过阈 | 289 | 13 |
| 分数未过阈 | 8 | 8 |

所以 Score Pd 为 `302/318=0.9497`，定位成功率为 `297/318=0.9340`，Joint Pd 为 `289/318=0.9088`。Joint Pd 是两个成功集合的交集，不是简单取两个比例的较小值。

### 9.2 BC-DPG 改变什么

BC-DPG 对同一候选热图施加空间统一的分数变化，不改变 argmax；raw DPG 与 BC-DPG 的预测距离/速度坐标逐样本相同。它可以通过改变目标是否过阈来改变 Joint Pd，但不能移动错误峰或减少某个样本的坐标误差。因此应写“改善检测决策并保持原候选坐标”，不能写“提高坐标定位精度”。

### 9.3 误差分布和灾难性尾部

| 指标 | 距离误差 | 速度误差 |
|---|---:|---:|
| MAE | 1.418 gates | 1.154 bins |
| median | 1 gate | 0 bins |
| P90 | 2 gates | 1 bin |
| maximum | 39 gates | 40 bins |

P90 与最大值的巨大间隔表明，大多数样本较准，但存在少量灾难性错误。MAE 或 median 都不能单独描述这种尾部；正式结果应补 P95/P99、maximum、CDF，并逐例审计极端样本的原始 IQ、标签、边界和预测峰。

误差 CDF（累积分布函数）把误差阈值 `e` 放在横轴，把“误差不超过 `e` 的目标比例”放在纵轴。例如曲线在 `e=2 gates` 处为 0.9，就表示 90% 的目标距离误差不超过 2 gates。CDF 能同时展示主体和长尾，比只给一个平均值更完整，但仍不能解释极端错误的成因。

只在 302 个过阈目标上计算时，距离和速度 MAE 分别降至 1.189 gates 和 0.834 bins。高分筛选排除了部分困难样本，属于条件统计；必须和全目标误差、Score Pd、Joint Pd 一起报告。

### 9.4 网格等价值与物理精度边界

当前网格使用 30 m/range gate 和 0.183 m/s/velocity bin，所以 MAE 可换算成约 42.54 m 和 0.211 m/s 的网格等价值。但真值已映射并四舍五入到离散网格，缺少未量化连续真值，雷达参数和标定也仍需核实。因此它们不是经过验证的真实物理测距/测速误差。

### 9.5 折间和描述性分层

Fold 1 的目标 Joint Pd 为 1.0、距离 MAE 为 0.4528 gates，但它的背景 Pfa 是最差折。这说明背景虚警和目标定位是不同性能维度。Fold 4 距离 MAE 为 2.6731 gates；Fold 6 Joint Pd 为 0.7917，体现另一类困难条件。

距离和速度分层显示近距离段及正向慢速段结果更好，负向快速段 Joint Pd 较低。这些切片没有参与选型，只能用于提出诊断假设，不能直接声称距离或速度造成性能差异。当前 manifest 没有 SNR 字段，不能补做正式 SNR 分层。

| 验收标准 | reviewer 能从图中判断哪些模式读取未来、哪些是 OOD 替换，并看到冷启动、丢帧、跨扫描和重启时的状态规则 |

### 10.1 标签无关不等于因果

BC-DPG 的 12 维扫描统计不读取标签，包括扫描样本数，raw score 的均值、标准差、中位数、分位数、最大值和过阈比例，以及分支差异和峰距离统计。但在线处理第 `t` 个样本时只能使用当前及过去数据；任何包含 `t+1...N` 的无标签统计仍是非因果信息。

### 10.2 四种上下文和训练分布

| 模式 | 上下文 | 证据角色 |
|---|---|---|
| complete-scan | 全扫描，含自身和未来 | 与正式训练匹配的离线上限 |
| leave-one-out | 除自身外的全扫描，仍含未来 | self-inclusion 敏感性诊断 |
| past-only | 假定顺序下的过去样本 | 顺序验证后才可能因果 |
| sample-independent | 不使用 12 维组特征 | 单独训练的在线导向参考 |

sample-independent BC 不是把 complete-scan checkpoint 的上下文临时置零。前者训练时始终处在无上下文分布并据此优化参数和选择 checkpoint；后者在推理时突然改变输入分布，属于 OOD 干预。OOD 是 out-of-distribution，即推理输入条件偏离模型训练时看到的分布；它不等于结果必然错误，但意味着该结果不能直接当作训练匹配条件下的部署性能。

### 10.3 冻结敏感性结果和选择边界

| 模式 | 虚警 | Joint 成功 | 与训练上下文匹配 |
|---|---:|---:|---|
| raw DPG | 186 | 289/318 | 是 |
| sample-independent BC | 122 | 289/318 | 是 |
| complete-scan | 56 | 289/318 | 是 |
| leave-one-out | 54 | 289/318 | 否 |
| past-only w4/w16/w64/all | 148/138/105/93 | 均为 288/318 | 否 |

leave-one-out 虽有 54 个虚警，但仍读取未来，且是 complete-scan 模型的 OOD 上下文替换。past-only all 的 93 个虚警也不能用来选择部署窗口：顺序未经验证、模型未按 past-only 训练，而且窗口结果来自已查看的测试数据。这里的 raw DPG 是 DPG-FCN 未校准分支，不是 Stage 4 的 Power2 baseline。

### 10.4 为什么真实采集顺序不可恢复

同一扫描内 sample ID 只有相同的组级秒值；MAT 中没有逐样本时间戳；MAT header 至少晚于文件名时间 49.1 天并紧跟文件 mtime，反映后期转换/保存；mtime 也会随复制改变。`beam_layer, azimuth_deg, sample_id` 只能产生确定排序，没有硬件日志证明它等于执行顺序。因此正式因果训练门保持关闭。

重新开启门禁需要逐样本 UTC 时间戳或单调硬件序号，并记录时钟分辨率、重置行为、丢帧情况及与 sample ID 的一一对齐。

### 10.5 冷启动和状态合同

past-only 中每个扫描首样本没有历史，71 个目标组和 6 个背景组至少产生 77 个零上下文起点。部署协议必须规定首样本判定、历史不足窗口时的处理、跨扫描清空、丢帧策略、时钟/雷达重启后的状态重置。不能只评价历史充分的样本。

### 10.6 三档采集合同

- `capture`：保证路径、标签、类别、H/V 通道和基础元数据可读取、可解释。
- `causal`：增加逐样本时间、硬件序号、scan/order、时钟与丢帧合同，验证真实顺序。
- `locked_evaluation`：再增加分区隔离、锁定测试、同日期/场地/雷达/标定条件的目标背景对照和 SNR 覆盖。

这里的 schema 是 manifest 必须遵守的字段合同，包括列名、数据类型、是否必填和取值约束。它描述“每条记录必须提供什么证据”，不等于数据内容本身。当前 manifest 在 locked profile 缺少 33 列，schema 为 FAIL；依赖 schema 的行完整性、事件时间、因果顺序、通道、分区隔离和同条件对照均为 BLOCKED。BLOCKED 表示前置证据不足，不能当作已经检查并通过或失败。

同条件类别对照属于 locked evaluation，因为它用于排除日期、场地、硬件配置或标定与标签耦合；只有同一条件同时出现目标和背景，类别效应才不至于被这些条件完全混杂。

### 11.1 从实验结果到贡献证据链

论文贡献不等于提出一个更复杂的模型名称。当前更可靠的论证顺序是：问题定义、共同基线、控制变量、消融、冻结评价和限制条件。主线是建立可审计的 H/V 候选检测、联合定位和复杂背景虚警抑制流程，而不是宣称所有支线都取得正结果。

### 11.2 BC-DPG 消融怎样归因

| 模式 | 六折虚警 | 主要审计对象 |
|---|---:|---|
| full | 56 | 完整离线扫描感知模型 |
| no scan context | 122 | 扫描上下文 |
| no background classification | 92 | 背景分类损失 |
| no background tail | 116 | 高分背景尾部损失 |
| no target keep | 59 | 单项目标保留损失 |
| no target protection | 50 | 目标保护组合：keep + pairwise + selectivity |
| no pairwise | 71 | 排序约束 |
| no shift selectivity | 44 | 选择性抑制约束 |
| no shift regularization | 35 | 抑制强度正则 |

这些名称对应当前 v3 损失中的不同约束：

| 概念 | 当前项目中的简要含义 |
|---|---|
| target shift | 目标候选平均被减去的 logit 量；越大越可能把真实目标压到阈值以下 |
| background classification | 让校准头判断候选更像背景还是目标，为 suppression 提供条件信号 |
| background tail | 惩罚校准后仍高于背景 margin 的高分背景候选 |
| target keep | 只惩罚超过允许量的目标实际扣分 `shift`，给小幅调整留出容忍区间 |
| pairwise | 鼓励校准后的目标 logit 相对背景 logit 保持规定的排序间隔 |
| shift selectivity | 鼓励背景候选的平均 `shift` 至少比目标候选更大一个 margin |
| target protection bundle | `target keep + pairwise + shift selectivity`；`no_target_protection` 会同时关闭这三项 |
| shift regularization | 惩罚全体实际扣分 `shift` 的均方，避免没有证据时也进行大幅压分 |

`full` 与 `no scan context` 在其他条件相同时的差异支持扫描上下文的增量作用；`full` 与 `no background tail` 支持尾部损失的增量作用。不能把 66 个差值笼统写成“整个网络结构的贡献”，也不能把各消融差值相加，因为模块可能交互，且这些仍是内部开发证据。

后几项虚警更低不代表应删除安全约束。无正则模型可能通过更激进地压低目标分数取得低虚警；最终选择必须同时看 target shift、Score/Joint Pd、最差折和目标保护，而不是只按虚警排序。

### 11.3 Power2 的 baseline 与 control 双重身份

Power2 是最早建立的主基线，为所有后续方法提供共同参照；它又是 Stage 3 固定架构表征比较和 Stage 4 `power2_roi_power_control` 的控制组，用于分离表示增量与 ROI 机制收益。它仍承担可靠的全图候选定位，ROI 还依赖其冻结候选。因此后续局部或校准模块不能把它从归因链中删除。

### 11.4 为什么负结果要保留

Stage 3 中 RI4 虽减少虚警，却明显损失 Joint Pd；Polar6/RI8 也未形成稳定综合优势。这支持的结论不是“极化无效”，而是“当前未完成绝对幅相标定的数据不支持复杂极化表示替代 Power2 负责全图检测”。这个负结果解释了为什么极化后来转入冻结候选 ROI，并防止只展示成功实验的选择性叙事。

### 11.5 五种证据标签

| 标签 | 当前例子 |
|---|---|
| historical development baseline | 早期 H/V/HV 固定划分 |
| development-fold screening | Stage 3 Fold 1/4 表征筛选 |
| internal grouped cross-validation | BC-DPG 六折；Stage 4 六折扩展但有选择复用 |
| post-test diagnostic | BC/ROI AND/OR、leave-one-out、past-only 窗口敏感性 |
| locked external blind test | 当前尚不存在 |

测试阈值未重调不能把其他开发反馈变成盲测。每个论文数字都应同时标明数据、fold、阈值、上下文和证据角色。

### 11.6 主结果、次结果和未来结果

主结果包括 raw DPG、sample-independent BC、complete-scan BC-DPG，以及 pooled/macro/worst-fold、Joint Pd、Pfa 和定位误差。Stage 3/4、上下文敏感性、零多普勒机制和灾难性定位审计属于次级消融或诊断。因果 past-only、外部跨日期盲测、空飘球载荷识别和绝对极化量仍是未来结果，不能提前写成贡献。

当前可复述的一句话主贡献是：

> 在 H/V 双通道 UAV/背景数据的六折分组内部开发评价中，本文建立了保持 DPG 候选坐标的目标保护扫描感知背景校准方法，将固定阈值背景虚警由 186/830 降至 56/830，并保持 289/318 的联合检测定位成功；由于完整扫描上下文可能包含未来样本，该结果仅代表离线扫描感知性能上限。

### 12.1 本科阶段的写作目标

大一项目论文不需要假装已经解决整个领域问题。最低而可靠的目标是：把研究对象说清楚，把数据到结果的过程讲通，给出可核对实验，并诚实说明尚未完成的部分。内部台账继续使用严格证据标签；正文只需在摘要、实验设置和局限性中各交代一次关键边界，不必每句话重复免责声明。

可采用较朴素的题目：

> 基于 H/V 双通道雷达数据的低慢小目标检测与背景虚警抑制研究

### 12.2 五章本科论文骨架

1. 绪论：问题、相关工作、本文完成内容；
2. 数据与基础方法：IQ、RD、Power2、标签和评价指标；
3. 检测与虚警抑制方法：DPG-FCN、sample-independent BC、complete-scan BC-DPG，ROI 作为扩展；
4. 实验与结果：划分和阈值、主表、消融、定位、Stage 3/4 与限制；
5. 总结与展望：当前前端成果，以及新数据、因果模型和空飘球方向。

这种结构已经足够支撑创新训练项目、课程论文或本科早期汇报。更细的七章结构可以在正式学位论文阶段再展开。

### 12.3 摘要与主结论

摘要可按问题、方法、协议、结果、边界五句话组织。当前结果句可以写：样本独立 BC 将 raw DPG 的背景虚警由 `186/830` 降至 `122/830`，完整扫描 BC-DPG 进一步降至 `56/830`，联合成功保持 `289/318`。最后说明完整扫描可能使用未来样本，因此属于离线扫描感知结果；这一句防止读者把数值误解成实时部署性能。

### 12.4 主图表和汇报结构

本科版本先完成六项核心图表：系统流程图、数据与划分表、Raw/独立 BC/完整 BC 主表、BC-DPG 消融表、六折异质性图、定位误差 CDF。Stage 3/4 极化结果可作为扩展表，数据合同和详细 claim boundary 可放附录。

十页汇报按“范围、数据、处理、DPG、虚警问题、BC 方法、主结果、消融与定位、限制、下一步”展开。标题尽量写成结论句，先讲问题和结果，再按追问深度进入代码。

### 12.5 三层复现交付

- 证据复核：报告、表格、图件、指标定义和模型选择台账可阅读；
- 指标重建：保留逐样本预测、fold、标签、阈值和生成脚本，可重新得到主表；

本科论文至少应做到第一层，并尽量做到第二层。受私有数据、checkpoint 或环境限制时，直接写明尚未达到完整重训练复现即可。

## 15. 参考答案（授课时后看）

以下答案是参考表述。正式报告应再补对应代码、实验配置和证据范围。

### 15.1 第一课

1. Doppler 由连续脉冲之间的慢时间相位变化体现，因此 FFT 沿脉冲轴（轴 0）进行；轴 1 已是距离门。
2. 1%/99% 分位数在每张图内部计算，归一化后保留相对强弱，原始幅度尺度和跨样本绝对功率不可由它恢复。
3. Hann 窗降低旁瓣泄漏，但主瓣变宽，邻近 Doppler 的分辨能力下降；它不消除旁瓣。
4. 越界通常说明标签、几何参数或数据质量有问题；背景表示没有目标，不能掩盖一个存在但无法映射的目标。
5. 有限时间记录相当于把无限信号乘以一个有限窗；时域相乘对应频域卷积，非整周期截断会使能量扩散到邻近频率。
6. 矩形窗主瓣较窄但旁瓣高；Hann 窗旁瓣较低但主瓣更宽，因而邻近频率分辨率下降。
7. 全零热图给模型提供明确的背景负样本，监督它在无目标时不要产生高峰；它不是“没有标签”，而是有意义的负监督。

### 15.2 第二课

1. `padding=1` 为每一侧补一个像素，`3x3` 卷积的输入输出空间尺寸相同；四层连续后仍是 `128x100`。
2. `1x1` 卷积只在当前位置混合通道，不访问邻近空间，因此不扩大感受野。
3. `min/max` 容易被一个极端离群点决定；分位数对极端值更稳健。它仍是相对归一化，不是绝对标定。
4. 高斯标签让真实点附近的预测受到连续、平滑的监督，允许网格量化和小定位偏差，不会把相邻格点当成完全无关的错误。
5. sigmoid 峰值是模型分数；当前训练标签和评价没有建立“该数值等于定位正确概率”的校准合同。
6. 卷积核是可学习参数，通过反向传播从训练数据中更新；滑动共享使同一个局部响应模式可以在整张 RD 图上复用。
7. GroupNorm 在每个样本内部按通道组归一化，对小 batch 的统计更稳定；BatchNorm 依赖 batch 统计，批量很小时容易抖动。
8. ReLU 会截断负值，LeakyReLU 为负值保留斜率，GELU/SiLU 提供更平滑的门控式非线性；具体优劣不能脱离训练和消融结果。
9. 该任务需要保留 RD 单元的空间对应关系；直接下采样会降低候选距离/速度坐标精度，即使之后上采样也可能引入定位误差。
10. 分数高只说明模型认为该样本有目标证据；距离或速度偏差过大时仍可能指向错误单元，因此 Joint Pd 必须加入定位容差。
11. 保留 logit 可使用数值更稳定的 `BCEWithLogits` 类损失，避免先 sigmoid 再取对数的数值问题；推理和阈值阶段再转换为分数。
12. 背景过多时，未加权损失可能被多数背景样本/像素主导，使模型偏向低分输出；权重用于调整监督贡献，但权重本身也必须审计和消融。

### 15.3 第三课

1. H/V 可能具有不同局部响应模式和噪声特性；独立分支允许分别学习、分别加载单通道 checkpoint，再由融合层利用互补信息。
2. `|H-V|` 描述分支响应差异；`H*V` 强调共同响应位置。二者是学习特征运算，不是原始复数 IQ 的直接极化物理量。
3. softmax 产生非负且和为 1 的样本级权重，形成受约束的相对选择；它不是空间门，也不是物理功率分解。
4. 辅助损失保留 H/V 分支自身的检测能力，防止融合头完全忽略一支或使分支退化成不可独立解释的特征提取器。
5. `0.2` 是当前工程配置中的经验超参数；它不是由物理公式推导，也不能仅凭当前结果倒推其最优性，应记录来源和损失量级。
6. 可以设计可学习权重，但它会增加自由度，可能导致某个辅助任务被自动降权、分支退化或在日期耦合数据上过拟合；应在合格新数据上预注册并做消融。

### 15.4 第四课

1. 背景虚警是部署约束；在预算内选最低可行阈值，才能在控制背景报警的同时尽量保留目标。
2. 不算 Joint Pd。还必须同时满足距离误差不超过 2 gates、速度误差不超过 3 bins。
3. AUC 只看目标/背景分数排序，不看峰的位置是否正确；Joint Pd 同时包含过阈和定位条件。
4. 反复查看测试集并挑选方案会把测试信息反馈到模型选择，导致性能估计乐观、可信度下降。
5. 只压低所有分数即可获得很低 Pfa，因此必须先设置 Joint Pd 保留门，防止以消灭目标为代价换取虚假的虚警改善。
6. Joint Pd 需要先满足过阈，再满足定位容差；它是 Score Pd 成功样本的子集，因此必然不大于 Score Pd。

### 15.5 第五课

1. v3 的 `shift` 对同一候选热图是空间统一标量。减去同一数不会改变任意两点的大小关系，所以 argmax 和坐标不变。
2. suppression-only 只能减分，不能把低 raw 分数提高到阈值以上；它的职责是压制背景候选，不是召回漏检。
3. complete-scan 可能读取当前样本之后的样本，实时系统在当前时刻无法获得这些数据；因此它是离线上限，不是因果部署结果。
4. 没有 Joint Pd 下限时，“所有分数归零”就是一个低 Pfa 的退化解；先守住联合检测定位能力，再比较 Pfa 才有意义。
5. `b` 由冻结 DPG 输出的当前样本统计经过校准 MLP 预测，是样本条件量，不是所有样本共享的全局常数；MLP 参数在训练集上学习。
6. 温度/偏置虽然不改变样本内排序，却会改变峰值的数值，因此会改变它是否超过冻结阈值，进而改变检测决策。
7. 当前损失监督的是目标存在/背景和检测行为，而不是独立的概率可靠性；要称真实概率还需要 ECE、Brier、可靠性图和独立校准数据。

### 15.6 第六课

1. RI4 虽然固定阈值虚警少，但 Score Pd、Joint Pd 和定位误差明显变差。Power2 既是原始基线又是共同控制组，最终选择要看综合任务指标。
2. `zdr_like_db` 由未完成绝对幅度/相位标定的 H/V 相对功率构成，只能称 relative 或 like 特征，不能写成绝对 ZDR。
3. 若 RI4 使用更大网络，结果混合了输入信息增益和容量增益，无法归因；固定容量是控制变量。
4. ROI 冻结全图候选和坐标，极化分支只做局部确认/抑制，减少了“检测、定位、表示”同时变化造成的归因混乱。
5. 不相同。补零只让张量形状和网络容量一致；活跃通道包含的信息、噪声和可辨识性仍不同。
6. 训练损失不降还可能由优化、学习率、归一化、标签或实现错误造成；需要学习曲线、容量消融和实现审计共同判断。
7. 网络容量是模型能够表达的函数类丰富程度；参数量、深度和宽度是常用代理，但参数数量不等于容量本身。还要考虑结构、归一化、优化和数据条件。
8. Power2 的基线身份说明所有改进都以它为共同参照；当前综合结果更可靠则说明它不仅是历史控制组，也仍是现阶段应保留的主检测方案。

### 15.7 第七课

1. 只比较 Power2 和 ROI RI4 会同时改变局部精修机制与输入表示；Power2 ROI 控制组用于测量 ROI 机制自身收益，RI4 相对它的差异才是输入信息的增量证据。
2. 数值零既可能是真实低响应，也可能是人工补零；`valid_mask` 标明数据支持范围，避免网络把边界缺失误当成目标或背景特征。当前实现只使用其均值 `valid_fraction`。
3. 非负 suppression 保证 refined score 不高于 raw score，固定阈值下低于阈值的背景不能被提升为虚警；但刚过阈值的目标可能被压到阈值以下而漏检。
4. BC-DPG 的观测虚警更少、联合成功更多；同时二者作用和部署条件不同，ROI 是样本独立局部抑制，complete-scan BC-DPG 是扫描感知离线上限。
5. Fold 1/4 的结果已经影响模式选择，把它们再计入六折汇总会带入选择偏差；真正独立盲测要求规则冻结后只在从未用于设计或选择的数据上评价一次。

### 15.8 第八课

1. pooled 让每条记录权重相同，因此记录较多的折贡献更大；macro 先算每折指标再平均，让每折权重相同。各折背景记录数不同时二者一般不相等。
2. median 只描述中间位置，不反映尾部严重程度；56 个虚警集中在 Fold 1/4，最差折 Pfa 达 0.28。六折数量也太少，median 为零不能外推到新环境。
3. Wilson 把同一扫描记录近似视为独立，忽略组内相关性，名义样本量被夸大；扫描组 bootstrap 更符合环境变化的层级。后者仍受只有 6 个背景组限制。
4. 分组划分避免同一扫描相邻记录跨 train/test 的组泄漏；但每一折的目标仍只来自 2 月 2 日、背景仍只来自 2 月 4 日，日期和类别无法在现有数据中分离。
5. 阈值未重调只避免了一类测试泄漏；所有 fold 已参与开发反馈，Fold 1/4 还用于模式筛选，因此测试数据已被选择过程消费。
6. 应在多个日期和场地同时采集目标/背景，保留真实时间戳、扫描与事件标识；在查看锁定测试结果前冻结模型、特征、阈值、组合规则和指标，并只评价一次。

### 15.9 第九课

1. 过阈但定位错误为 `302-289=13`；定位正确但未过阈为 `297-289=8`；两者都不满足为 `318-(289+13+8)=8`。
2. BC-DPG 改变分数是否过阈，所以 Joint Pd 可以变化；空间统一变换保持 argmax 和坐标不变，因而没有改善坐标误差。
3. 过阈样本通常更容易，按分数条件化会排除部分困难目标并产生选择偏差；条件 MAE 必须与全目标误差、Score Pd 和 Joint Pd 同报。
4. median/P90 描述主体分布，却看不到少量灾难性尾部；39-gate 错误会影响安全性，也可能暴露标签、数据、边界或模型失败机制，需要逐例审计。
5. 当前误差比较量化后的网格索引，连续真值、量化误差和物理标定尚未分离，所以米制换算只是离散网格偏移的等价值。
6. 背景虚警和目标检测定位是不同维度；系统评价必须分别报告 Pfa、Score Pd、定位误差和 Joint Pd，并检查各自的困难 fold。

### 15.10 第十课

1. Leave-one-out 仍使用当前时刻之后的样本；complete-scan checkpoint 未按该上下文训练；结果又是测试后 OOD 敏感性诊断，因此不是因果部署证据。
2. past-only 顺序仅由 beam/azimuth/sample ID 推断，complete-scan checkpoint 未按 past-only 训练，且 `4/16/64/all` 均已在测试侧查看；不能据此选择 `all` 或与独立训练模型作确认性胜负声明。
3. 单独训练模型在无组上下文分布中优化参数、损失和 checkpoint；临时置零会破坏 complete-scan 模型的训练输入分布，模型可能已依赖组特征，属于 OOD 干预。
4. MAT 没有采集时间变量；header 晚于采集至少 49.1 天且贴近 mtime，二者反映转换、保存或复制，不是硬件采集时钟。
5. 每个扫描首样本没有历史；协议需规定首样本、历史不足、跨扫描清空、丢帧、时钟/雷达重启和状态恢复规则。
6. capture 保证记录完整可解释；causal 保证真实有序上下文；locked evaluation 再保证冻结分区和可归因评价。同条件目标/背景对照用于拆开类别与日期、场地、雷达配置和标定混杂。

### 15.11 第十一课

1. `full/no_scan` 支持扫描上下文的条件增量，`full/no_tail` 支持背景尾部损失的条件增量；消融只隔离指定模块，模块存在交互，差值不能相加或泛化成整个结构的独立效应。
2. 更低虚警可能来自更激进的目标压分；应同时检查 target shift、Score/Joint Pd、最差折和安全约束。固定 `0.01` 是当前更保守一致的方案。
3. 负结果界定了复杂极化全图输入在未标定数据上的限制，并直接支撑 Power2 保留和 ROI 转向；删除它会造成选择性报告和设计动机断裂。
4. Stage 3 是 development-fold screening；Stage 4 六折是带 Fold 1/4 选择复用的 internal grouped cross-validation；BC/ROI OR 和 past-only 均是 post-test diagnostic。
5. 在六折分组内部开发评价中，target-protected scan-aware BC-DPG 将固定阈值虚警从 186/830 降至 56/830并保持 289/318 Joint 成功；complete-scan 可能使用未来样本，所以只代表离线上限。
6. Power2 是所有改进的历史共同锚点，也是隔离表征和 ROI 机制增量的控制组；Stage 3 未证明复杂表示能替代其全图定位，Stage 4 仍依赖其冻结候选。

### 15.12 第十二课

1. 没有划分、阈值来源和指标定义，`56/830` 无法判断是验证还是测试、阈值是否重调、分母是什么，也不能和其他方法公平比较。
2. 五句话依次说明问题、方法、评价协议、核心结果和适用边界；离线边界防止把 complete-scan 误解为当前时刻可获得的实时性能。
3. raw DPG 给出未校准基线，sample-independent BC 给出在线导向增量，complete-scan 给出扫描上下文离线上限；三者共同分离校准和上下文的作用。
4. 证据复核只核读现有产物；指标重建从冻结逐样本预测重新计算表图；完整复现还需原始数据、checkpoint、环境和训练/推理流程。
5. 当前 sample-independent BC 更接近在线条件；完整 BC-DPG 可能使用未来样本，只能离线运行。严格实时性能要在真实时间戳上训练 past-only 模型并做锁定测试。
6. 本项目基于 H/V 双通道 UAV/背景雷达数据研究目标检测、距离—速度定位和背景虚警抑制。DPG-FCN 提供候选，目标保护 BC 在固定坐标上降低背景分数。六折内部结果中，sample-independent/complete-scan BC 将 raw DPG 的 186 个虚警降至 122/56 个，并保持 289/318 联合成功。完整扫描是离线上限，跨日期泛化、因果部署和空飘球识别仍需新数据验证。

## 17. 常见误区与故障排查

先判断自己拿到的是什么材料，再决定能运行什么。路径或测试不存在不一定是代码故障，也可能是当前材料本来就不包含完整仓库内容。

### 17.1 先识别材料层级

| 材料 | 常见识别线索 | 允许完成 | 不能据此完成 |
|---|---|---|---|
| 完整 Git 仓库 | 有 `.git/`、`tests/`、`scripts/`、`models/` 和项目控制文件 | 查看源码、运行已有测试和无数据接口检查；有授权输入时按协议重建证据 | 仅凭 Git 不能假定本机已有原始数据、checkpoint 或训练权限 |
| V15 项目分享包 | 有 `MANIFEST.json`、`SHA256SUMS.txt`、汇总文档和脱敏 evidence | A 级证据阅读、哈希校验、表格与结论边界复核 | 完整训练、逐样本重放、从包内重新得到论文性能 |
| 算法代码审阅包 | 无数据、范围更窄，README/manifest 明确列出可审阅算法和 smoke 入口 | 代码接口、数学不变量和合成 smoke 复核 | 主项目状态复核、真实数据性能或完整仓库测试 |

不要根据 ZIP 名称猜材料类型；先读根目录 README、manifest 和校验文件。材料权限层级还应对照 `docs/TEAM_REPRODUCTION_GUIDE_ZH.md`。

### 17.2 命令和环境问题

| 现象 | 先检查 | 正确处理 | 禁止做法 |
|---|---|---|---|
| 找不到 `check_project_health.py` | 是否在完整仓库根目录；正确路径是 `scripts/check_project_health.py` | 用 `pwd` 和 `git rev-parse --show-toplevel` 确认根目录，再检查该路径；若材料没有 `.git` 或该脚本，返回 README 的允许入口 | 从其他版本随便复制同名脚本，或把“脚本不存在”写成健康检查通过 |
| `pytest` 找不到测试 | 是否存在 `tests/`，是否从仓库根目录执行 `python -m pytest` | 完整仓库按 `pytest.ini` 运行；分享包或算法包只运行其 README 明确列出的测试/smoke | 因收集到 0 个测试就声称项目测试通过，或临时下载不匹配的测试 |
| 只有 V15 分享包 | 检查 `MANIFEST.json` 和 `SHA256SUMS.txt` | 完成哈希、文档、CSV 和图件证据复核，并把复现等级写成 A | 寻找不存在的内部训练脚本、原始数据和 checkpoint |
| 没有原始数据或 checkpoint | 查看数据卡、复现指南和任务权限 | 只做静态代码检查、合成 smoke 或冻结证据阅读；需要性能重建时向负责人申请对应材料 | 用随机/模拟数据生成“项目性能”，或直接启动正式训练 |

### 17.3 表述和研究边界问题

| 常见误写 | 为什么错误 | 应改成 |
|---|---|---|
| 把 Score Pd 写成 `fusion Pd` | Score/Joint 是同一输出的两种成功口径，不是单通道/融合之分 | “Score Pd 只检查过阈；Joint Pd 还要求定位正确” |
| 把 `zdr_like` 写成绝对 ZDR | 当前缺少 H/V 绝对增益、相位和相干标定 | “未标定的相对极化/ZDR-like 特征” |
| 把 `56/830` 写成每小时虚警率 | 当前分母是背景记录，没有统一观测时长和事件合并合同 | “830 条背景记录中有 56 条过阈”或样本级 Pfa |
| 把 complete-scan 写成实时模型 | 它可能读取同一扫描中的未来样本 | “离线扫描感知性能上限”；在线导向参考是单独训练的 sample-independent BC |
| 把 Stage 3 写成六折泛化 | Stage 3 只在 Fold 1/4 做开发筛选 | “两折开发证据”；不得升级成六折或外部泛化结论 |
| 把 Stage 4 六折写成独立盲测 | Fold 1/4 先用于选模式又进入六折汇总 | “带选择复用的六折分组内部评价” |
| 把算法包、V15 分享包和完整 Git 混为一谈 | 三者包含内容、权限和可复现等级不同 | 先写明材料类型，再报告实际执行的校验、测试或复现等级 |

出现未列出的故障时，提交最小问题记录：材料类型、当前目录、完整命令、完整错误、环境名、代码提交或 manifest 版本，以及是否具备数据/checkpoint 权限。不要通过换数据、改阈值或删除报错来“修复”证据问题。

后续新增课程应在本文件末尾追加，并至少补充：学习任务卡、目标、代码入口、实验边界、课堂问题、参考答案和对应 `TASK_BOARD` 任务。
