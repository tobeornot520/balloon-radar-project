# 多域特征候选放行门 V1

版本：2026-08-02  
依据：`multidomain_feature_catalog_v1` 的 1,148 条检测记录、56 项特征目录、六个背景扫描组压力检查，以及现有 H/V 通道有效性限制。

## 决策

**当前不放行任何基于多域标量特征的正式融合训练或性能宣称。**

这不是说特征“没有信息”。当前候选局部零多普勒形态有很强且跨六个背景扫描组一致的
区分现象，但 UAV 与背景采集日期完全混杂，且六个背景折都已参与开发。它只能支持背景
机制诊断和固定、可解释的抑制设计，不能证明新的学习型分类器可泛化。

相对极化量可以保留为未来候选 ROI 辅助分支，但不得单独作为检测器，也不得称为绝对
ZDR、PhiDP 或经标定散射物理量。相位类通道在 H/V 相干、同步和幅相标定得到设备证据前
保持关闭。

## 下一次小模型的条件放行

下列条件必须全部满足，才可以对新的、未消费开发数据训练最小特征融合或 ROI 确认头：

1. H/V 通道含义、是否同步复数 IQ、PRF 和速度轴有可引用设备说明；
2. 每个极化通道有 `channel_validity`，未验证的相位量输入为零且不能影响输出；
3. 目标与背景在同日期/场地采集，并按 session/scan 外层隔离；
4. 特征定义、缺失值规则、归一化拟合范围、主指标、阈值和停止规则在读取外层测试前冻结；
5. 只在训练/验证组选择特征与模型；外层评价只运行一次；
6. 主验收同时报告 Pfa、joint Pd、最差背景组、定位误差和配对新增/移除误警；
7. 相对于 Power2/固定安全基线，困难组 Pfa 降低且 joint Pd 不下降，或预先写明容差并通过负责人审核。

任何一项不满足时，输出应记录为 `BLOCKED` 或机制诊断，而不是用更多 epoch、更多通道或
更深网络掩盖数据条件缺口。

## 可复跑证据

当前证据由以下入口生成或核对：

- `scripts/build_multidomain_feature_catalog_v1.py`：特征目录、背景组压力表和来源依赖表；
- `features/multidomain_radar_features.py`：候选局部及多域特征定义；
- `scripts/audit_polarimetric_features_v1.py`：H/V 相对特征与命名边界；
- `docs/MULTIDOMAIN_CURRENT_DATA_MINING_V1.md`：当前数据挖掘的完整解释；
- `PROJECT_CONTROL/TASK_BOARD.md`：D05、D06、D07 的持续状态。

本记录冻结的是**当前数据上的决策边界**，不是永久否定极化、时域或微多普勒路线。新数据
满足上述门后，应建立 V2 记录，而不是修改本文件以追溯性放行旧结果。
