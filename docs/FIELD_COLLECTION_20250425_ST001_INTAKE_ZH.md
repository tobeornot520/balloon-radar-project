# ST001 2025-04-25 学姐实验数据入库与预研模型报告

更新时间：2026-09-24  
资料编号：`field_collection_20250425_st001`  
资料性质：学姐既有实验数据；不是本项目定向采集实验

## 1. 结论先行

本批学姐实验数据已经完成原始文件入库和 RSTM 头部审计。它包含同一站点、同一天的五类目标 IQ 记录，以及配套的 RHI/PPI 背景 IQ 和连续背景产品。对我们项目而言，它是可用于熟悉雷达文件、开发读取器、检查信号处理流程和做初步方法预研的外部资料，不是本项目已经完成的一次正式采集。

这批数据目前不能直接作为本项目训练集、论文最终测试集或外场实验结果，原因是：它原本不是按本项目的问题设计的，类别与采集时间完全混杂，所有目标来自同一站点同一天，目录名还没有独立标签证明，且 RSTM 载荷的 H/V 含义、物理距离/速度轴和标定状态尚未得到设备方确认。因此本报告中的模型结果只称为**学姐数据上的探索性预研结果**。

## 4. RSTM 头部审计结果

入库脚本 `scripts/intake_rstm_field_collection.py` 只读取头部，不改写原始文件。已记录：

- `RSTM` 魔数、版本字段和头部类型；
- 站点 ID（均为 `ST001`）和头部站点名称（`成都远望`）；
- RHI/PPI/RPI 等扫描字段；
- 头部 Unix 时间与文件名时间；
- 头部三个尺寸/配置整数（暂以偏移命名，未擅自解释为 H/V、脉冲数或距离门数）；
- 原始文件大小和可选 SHA-256。

文件名时间与头部时间多数接近，但存在明显偏差：背景 RHI 约 `-5928 s`，部分目标组约 `-165 s`、`-1069 s` 和 `-1339 s`。这可能与扫描开始时间、文件封装时间或头字段语义有关，不能把任一字段直接当作逐脉冲采集时间。需要设备方提供 RSTM 格式说明和时间字段定义。

当前仍未确认：

1. 文件中的两个交错浮点分量是否为同一通道的 I/Q，还是多通道/产品字段；
2. 是否存在 H/V，通道排列、同步关系和相对幅相标定；
3. RHI/PPI/RPI 的距离、方位、俯仰和速度物理轴；
4. 记录块边界、每条径向的头长度和载荷编码；
5. 逐脉冲 UTC、硬件序号、丢帧与重启信息。

## 6. 开发模型设计与已完成训练

### 6.1 当前可复现基线

脚本：`scripts/train_rstm_target_baseline.py`  
配置：`configs/rstm_target_baseline_v1.json`

输入是每个 IQ 文件一个样本。读取器从已探测的 RSTM 载荷起始候选偏移 `0x860` 采样固定块，并对交错分量计算均值、标准差、分位数、幅度和分块 RMS 等统计特征。由于记录元数据可能与载荷交错，特征提取只保留有限且绝对值不超过 16 的样本，避免把元数据整数误解释成 `1e38` 级浮点异常值。当前分量名称为 `component_a/component_b`，**不称 H/V**。这一步的目的只是验证读取和建模流程，不是建立本项目的正式识别器。

评估按每个来源目录内部的文件名时间顺序划分，最后一个时间五分位留作测试；没有把同一文件随机切片到训练和测试两边。

### 6.2 训练结果

结果目录（本地生成，模型权重不进入 Git）：

`results/experiments/rstm_target_baseline_20250425/`

| 任务 | 训练/测试文件 | Accuracy | Balanced Accuracy | Macro F1 |
|---|---:|---:|---:|---:|
| 五类目标来源分类 | 380 / 92 | 0.565 | 0.503 | 0.473 |
| 气球 vs 其他目标来源 | 380 / 92 | 0.957 | 0.955 | 0.940 |

二分类结果说明当前特征接口和训练流程可以运行，不说明气球识别已经完成，更不说明本项目已经完成气球实验。五类目标和气球二分类都受到同日、同站点、按时间连续采集的混杂影响；测试段并不是独立日期或独立场地。

五类测试段的逐类召回为：气球 `20/21`、反射靶 `2/15`、六翼设备 `21/35`、小卫星 `8/11`、无人机 `1/10`。主要混淆发生在反射靶、六翼设备和无人机之间；这说明当前统计特征尚不足以支持稳定的细粒度目标识别。气球二分类测试段为气球 `20/21`、其他目标 `68/71`，只应作为接口和数据质量的开发诊断。

### 6.3 下一阶段模型路线

1. **先把学姐数据用作格式和流程练习**：根据设备文档解析径向/脉冲/距离门边界，验证 I/Q 组织，再尝试生成 Power2、RD 和时频图。
2. **再做本项目定向采集**：按照我们的目标、背景、天气、场地和同步要求重新设计实验。
3. **正式检测基线**：用本项目同配置目标与背景配对，先训练 Power2/RD 的二分类或检测模型；按文件、扫描段或 session 分组。
4. **正式类别识别模型**：在本项目至少两个日期或两个 session 中重新训练气球/其他目标分类，比较单域 Power2、RD、STFT 和多域融合。
5. **部署模型**：只有在逐样本时间顺序、丢帧处理、跨扫描状态清空规则和锁定测试集齐全后，才评价实时性和因果历史模型。

## 7. 训练前必须补齐的证据

- RSTM 设备格式文档、记录块结构和载荷类型；
- H/V 通道说明、同步方式和标定记录；
- PRF、采样率、载频、脉冲数、距离门、方位/俯仰轴；
- 每个目标 session 的真实类别、起止时间、位置/速度/角度真值；
- 目标与背景的同配置配对 session；
- 气象记录（风、降水、能见度、温湿压）及其时间同步；
- 逐样本硬件序号、UTC、丢帧和重启日志；
- 至少一个从未参与设计的新日期/场地 locked test。

在这些证据到位前，不应把当前结果写成“空飘球载荷识别性能”“跨环境泛化”或“实时部署性能”。
