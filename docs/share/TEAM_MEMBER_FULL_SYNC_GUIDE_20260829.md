# 全员项目同步包说明

日期：2026-08-29  
对象：当前全体项目成员

这套材料是本轮项目同步的正式分发版。它覆盖当前项目的研究定位、开发历史、结果与边界、任务台账、课程、采集方案、核心源码、配置、测试和冻结聚合证据。

证据包保留可阅读的报告、主结果表、消融与定位汇总表及图；不包含只用于负责人审计的逐样本来源、实验目录、权重哈希和输入文件哈希明细。这样每位成员能理解和审查项目结论，同时不会把受控资料或历史噪声混入日常协作材料。

## 必须获取的三个包

1. `01_项目资料与研究证据`：理解项目整体、当前成果、失败与限制、论文和下学期任务；
2. `02_工程源码与配置`：查看当前工程实现、训练/评价入口、配置和测试；
3. `03_外场数据合同与执行模板`：执行设备确认、同步、标定、Pilot 和新数据记录。

## 这次为什么仍然有筛选

“全员同步”不等于无边界复制整个硬盘。以下材料不会放入公共成员包：

- 原始 H/V IQ、视频、标签、逐样本预测、checkpoint 和训练日志；
- 合作方场地、设备、人员和事件的受控资料；
- `PROJECT_CONTROL/logs/` 中的历史聊天/开发导出；
- 逐样本来源、内部实验路径、checkpoint 哈希和输入文件哈希等负责人审计明细；
- 原始参考书、论文 PDF、PPT 和可能受许可限制的公开数据档案；
- `data/`、缓存、构建产物和旧分享包。

这些材料要么涉及数据权限与隐私，要么无法支撑独立复现，要么会让成员被历史噪声淹没。需要时按项目角色和受控流程申请。

## 成员应如何使用

1. 先读 `01_项目资料与研究证据/README.md`，再读同步简报、当前状态、任务台账和课程入口；
2. 需要开发时，读 `02_工程源码与配置/README.md` 和根 `README.md`，不要在无原始数据或 checkpoint 的情况下声称复现了性能；
3. 准备外场时，以 `03_外场数据合同与执行模板/README.md`、SOP 和 manifest 模板为准；
4. 任何新实验都要记录数据版本、分组、配置、代码版本、阈值和结果，不能从已经阅读的冻结测试结果反向选模型。

当前成果属于 H/V UAV/背景的内部开发证据。空飘球载荷识别、绝对全极化、严格实时和跨环境盲测仍等待新同步标定数据。

## 构建入口

全员包由 `scripts/build_team_sync_package.py` 生成。此前按角色拆分的试行包已经归档，避免成员拿到不同范围后形成第二套项目认知。
