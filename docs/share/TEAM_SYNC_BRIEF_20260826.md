# 项目同步简报：现有成果、开发思路与下一步

日期：2026-08-26  
对象：项目组成员  
阅读时间：约 10 分钟

## 先说结论

当前项目已经形成一套可审计的 H/V 双通道雷达目标检测、距离--速度定位与背景虚警抑制前端；它为后续空飘球载荷识别准备了数据、特征和模型接口，但**尚未完成空飘球有载/无载或载荷类型识别**。

当前最好的六折内部开发结果是完整扫描上下文的 BC-DPG v3：背景虚警为 `56/830`，检测与定位联合成功为 `289/318`。它可能使用同一扫描中当前样本之后的信息，因此只能称为**离线扫描感知性能上限**，不能写成严格实时部署结果。

## 我们在解决什么问题

雷达的 RD 图上，真实低慢小目标与复杂背景峰可能很像。项目并非只追求一个更高的分类分数，而是同时要求：

- 找到目标；
- 距离和速度定位正确；
- 控制复杂背景虚警；
- 清楚交代模型是否使用未来信息、数据是否存在日期/场地混杂；
- 为之后的空飘球、载荷、时频和相对极化研究建立可靠入口。

## 已形成的开发链

```text
H/V 复数 IQ
  -> 慢时间 FFT 与 RD 表示
  -> Power2 / Simple FCN 基线
  -> H/V 双分支门控 DPG-FCN 候选检测
  -> 目标保护背景校准和 ROI 局部精修
  -> 分组评价、虚警/定位/因果审计
  -> 新数据合同与未来多域融合接口
```

开发过程中，项目坚持把“工程模块已经写好”“开发数据上看到的现象”“能被新数据独立验证的结论”分开记录。这样可以避免模型只学到日期、文件来源或场地捷径。

当前现有 UAV/背景数据中，目标和背景采集日期完全耦合，且背景独立扫描组只有 6 个。因此任何现有数值都只能称为**内部开发阶段证据**，不能宣称跨日期、跨场地或外部盲测泛化。

## 为什么不直接上最复杂的多域模型

多域融合是下一主阶段，但首先必须完成公平比较：RD、时域、时频、相对 H/V 特征各自能解决什么问题？融合后是否真的降低困难背景虚警、提高联合检测定位或分类表现？收益是否覆盖增加的延迟和资源消耗？

拟采用的比较顺序是：

1. 强单域基线；
2. 同条件的简单拼接；
3. 门控或交互注意力融合；
4. 逐域消融、最差场景、延迟/吞吐和内存比较。

只有在冻结的数据划分与评价规则下证明稳定增益，才把“多域优越”写进论文或汇报。

## 下学期主线

```text
数据与实验合同
  -> 多域融合的公平增益证明
  -> 气象/场地因素量化与鲁棒性
  -> 因果流式测速、测距、测角与工作站实时演示
  -> 专家审阅、锁定测试和应用验证
```

气象和场地首先作为元数据、分层条件和可能的混杂因素；不默认把“天气识别”扩成新的模型任务。对象识别也采用分层路线：目标/背景，空飘球/非空飘球，有载/无载，最后才是载荷状态或类型。

## 新数据最重要的原则

每次实验都需要同步保存雷达原始数据、真实 UTC 时间、硬件序号、视频/真值、气象、场地、对象构型、配置和标定信息。每个日期、场地和配置下都要同时采集目标与背景，最终再预留从未参与设计的 locked test。

第一次外场更适合小组进行设备学习、场地勘察和最小试采；四场景 Pilot 通过同步、标定和数据质量检查后，再扩大正式采集。
