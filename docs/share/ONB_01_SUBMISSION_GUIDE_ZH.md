# ONB-01 入组验收提交说明

版本：2026-08-06

## 1. 任务性质

`ONB-01` 是入组验收任务，不是模型训练任务。它用于确认成员已经理解项目边界、能够复核
基本证据，并能在停止条件下认领一个正式任务。

完成 ONB-01 不需要下载原始雷达数据、申请 checkpoint、训练模型或提交准确率。

## 2. 成员需要提交什么

每位成员提交一个以自己姓名或成员编号命名的文件夹，里面包含以下三项：

### 2.1 个人入组清单

从 `team_onboarding_checklist_template_v1.csv` 复制一份，填写一行自己的记录。至少填写：

- `member`、`reviewer`；
- 分享包 SHA256 是否通过；
- 一页摘要、当前状态、证据边界是否读懂；
- 环境、项目健康检查和 `pytest` 是否通过；
- 准备认领的 `task_id`；
- 当前疑问、剩余缺口和下一动作。

建议文件名：`<成员编号>_onboarding_checklist.csv`。

### 2.2 五问口头验收记录

由 reviewer 在口头交流后填写一份简短记录，或在成员记录中补充 reviewer 栏。记录每题的
结论应为 `pass`、`needs_followup` 或 `fail`，并写一句证据依据。五问是：

1. 为什么当前 `56/830` 不能称在线部署性能；
2. 为什么 Tian 2024 不能称精确复现成功；
3. 为什么当前 H/V 不能直接称绝对极化特征；
4. 为什么 LAT-MRICD 不能随机拆行；
5. D17-XBAND 为什么是 `FAIL_STOP`，现在还能做什么。

建议文件名：`<成员编号>_oral_review.md`。

### 2.3 任务认领表

从 `team_task_claim_template_v1.csv` 复制一份，提出一个正式任务。任务必须来自
`TEAM_START_HERE.md` 第 7 节，且状态不能是“已完成”或“外部阻塞；当前不可获得”。

至少填写：

- `task_id`、`title`、`owner`、`reviewer`、`priority`；
- 输入路径或 manifest、输入哈希；
- 计划输出、分组键和测试集访问规则；
- 主指标、完成门、停止条件和禁止表述；
- 目标日期、阻塞项、下一动作。

建议文件名：`<成员编号>_task_claim.csv`。

任务表提交后不是自动批准。负责人和 reviewer 需要确认范围、数据权限和停止条件，填写
`review_decision` 后才算正式认领。

## 3. 当前任务选择规则

当前最适合所有新成员的任务是 `ONB-01` 本身。完成入组后，可申请只读复核类任务，例如
`PUB-DAUR`、`PUB-HSR`、`PUB-FMCWR2` 或 `PUB-DRONERFC`。这些任务只能复核审计、分组和
禁止训练边界，不能自行改成模型训练任务。

以下任务当前不能直接认领为正式建模：

- `D01-D02`：缺少设备方 H/V、IQ、PRF 和坐标事实；
- `D10`：Tian 精确复现冻结，等待合格对齐材料；
- `D17-XBAND`：S/Ku locked target 已消费，只能复核证据；
- 已标记“已完成”的 `D04-P0`、`D17-NX`、`D17-HX`。

## 4. 负责人验收清单

收到成员材料后，负责人只需确认：

| 检查项 | 合格条件 |
|---|---|
| 入组清单 | 字段完整，SHA256/测试结果有记录，疑问没有被隐去 |
| 五问记录 | 至少 4 题达到基本要点，第 2、3 题不能越过证据边界 |
| 任务认领表 | 有 owner、reviewer、输入、输出、分组、完成门和停止条件 |
| 权限边界 | 没有索要 locked test、原始数据或 checkpoint 的不必要副本 |
| 最终决定 | `approved`、`needs_followup` 或 `rejected`，并写明理由 |

只有三项材料齐全且 reviewer 批准，成员才进入下一阶段角色分配。试做允许得到负结果，
但必须如实记录命令、失败原因和不能声称的结论。

## 5. 可直接发送给成员的消息

> 请先完成 ONB-01 入组验收，不需要下载数据或训练模型。请提交三项材料：个人入组清单、
> 五问口头验收记录、任务认领表。任务只能从 TEAM_START_HERE 第 7 节选择，且需要负责人
> 和 reviewer 确认输入、输出、完成标准和停止条件。材料齐全后再分配正式任务和数据权限。
