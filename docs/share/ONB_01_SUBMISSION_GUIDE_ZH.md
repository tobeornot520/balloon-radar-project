# ONB-01 基础入组确认说明

版本：2026-08-07 V2（随 V15 分享包发布）

## 1. ONB-01 的边界

`ONB-01` 是基础入组或继续参与确认，不是研究任务、最小试做或长期任务认领。

它只确认成员已经收到唯一验收包、理解项目当前边界，并能回答五个基础问题。通过后表示完成
项目内部的基础入组确认；学校正式名单、署名、评奖和学分仍由指导老师及学校规则决定。

ONB-01 不要求下载原始数据、申请 checkpoint、训练模型、提交准确率、完成最小试做，或填写
正式任务认领表。

## 2. 成员需要提交什么

ONB-01 只需要两项材料。

### 2.1 个人入组清单

填写 `assets/templates/team_onboarding_checklist_template_v2.csv` 中的一行，至少包括：

- `member`、`reviewer` 和开始日期；
- 包名、包 SHA-256 和校验是否通过；
- 一页摘要、当前状态和证据边界是否理解；
- 当前数据访问等级和是否拥有完整仓库权限；
- 五问记录路径、通过题数、剩余疑问和下一动作。

只有分享包权限时，环境、项目健康检查和 pytest 字段填写 `not_applicable`，不能伪造为
`pass`。只有获得完整仓库权限时才执行这些工程检查。

建议文件名：`<成员编号>_onboarding_checklist.csv`。

### 2.2 五问回答与 reviewer 记录

成员可以先提交书面回答，reviewer 再用简短口头追问确认是否真正理解。每题记录为
`pass`、`needs_followup` 或 `fail`，并写一句依据：

1. 为什么 `56/830` 不能称为严格实时部署性能？
2. 为什么 Tian 2024 不能称为精确复现成功？
3. 为什么当前 H/V 不能直接称为绝对极化特征？
4. 为什么 LAT-MRICD 不能随机拆行，D17-XBAND 又为什么不能重跑 S/Ku？
5. 当前还能做什么、不能做什么？

建议文件名：`<成员编号>_onboarding_review.md` 或保留原始 DOCX，并由 reviewer 另存评审记录。

## 3. 判定规则

| 决定 | 条件 | 下一步 |
|---|---|---|
| `pass` | 包哈希通过；五问至少 4 题通过；第 2、3 题没有越过证据边界 | 完成基础入组确认，可另行安排最小试做 |
| `needs_followup` | 存在可修正的理解或材料缺口 | 只补原缺口，不重做已通过内容 |
| `rejected` | 补充后仍不能理解基本边界，或材料存在明确伪造/泄露 | 暂停内部材料与后续角色评估 |

哈希失败或版本不一致时先更换为负责人发布的唯一版本，成员不得为发布端错误承担责任。

### 3.1 已使用 V13/V14 的成员

旧包曾出现同名文件内容不一致。已经提交过材料的成员不需要从头重做：reviewer 保留其中可核验
的个人清单和五问记录，只要求成员改用唯一 V15 重新完成包名/SHA-256 校验，并补齐 V2 清单中
原材料确实没有覆盖的字段。旧材料没有正式任务认领表不构成缺项；已经填写过的长期任务意向也
不作为 ONB-01 通过或不通过的依据。

## 4. ONB-01 之后的三个独立动作

### 4.1 最小试做

通过 ONB-01 后，负责人从 Q1-Q6 中分配或与成员协商一个 3-6 小时的短期试做。试做使用
`assets/templates/team_trial_task_template_v1.csv`，用于了解成员适合的角色和初始权限。

最小试做不是入组条件，也不是长期任务；试做得到负结果不等于不合格，只要过程真实、可复核。

### 4.2 角色与权限确认

reviewer 根据试做产物填写 `team_qualification_scorecard_template_v2.csv`，决定核心候选、执行、
观察/补验等角色及最小必要数据权限。该决定不追溯改变 ONB-01 的入组结论。

### 4.3 正式长期任务认领

只有角色和权限确认后，才使用 `team_task_claim_template_v2.csv` 认领正式任务。正式任务必须有
owner、reviewer、输入、输出、分组、测试访问规则、完成门和停止条件。

长期任务属于项目分工，不属于 ONB-01 验收。

## 5. 负责人验收清单

| 检查项 | 合格条件 |
|---|---|
| 唯一版本 | 包名和 SHA-256 与负责人公告一致 |
| 入组清单 | 身份、阅读、权限、五问和缺口字段完整 |
| 五问记录 | 至少 4 题通过；第 2、3 题不越界 |
| 环境字段 | 分享包权限填 `not_applicable`；完整仓库权限才填写真实运行结果 |
| 最终决定 | `pass`、`needs_followup` 或 `rejected`，并记录原因 |

验收时不得要求成员认领长期任务，也不得因分享包缺文件、同名版本不一致等发布问题扣分。

## 6. 可直接发送给成员的消息

> 记录，不需要认领长期任务。通过 ONB-01 后即完成项目内部的基础入组确认；随后会另行安排
> 一个 3-6 小时的最小试做，用于匹配角色和权限，试做结束后才讨论正式任务分工。
