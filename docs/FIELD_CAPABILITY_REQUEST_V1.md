# 双极化雷达采集能力确认单 V1

日期：2026-07-29

用途：确认设备是否能够支撑空飘球载荷研究所需的时域、极化和微多普勒数据。请设备
负责人提供可追溯答复和附件；未知项可写“待实测”，不要根据旧文件猜测。

## 一、设备与配置

请提供：

1. 雷达厂家、型号、序列号、固件版本和采集软件版本；
2. 工作频段、中心频率、PRF、带宽、脉冲宽度、每帧脉冲数、距离门数和距离分辨率；
3. 一帧、一个波束、一次扫描和一个输出文件之间的关系；
4. 当前可导出的配置文件、操作手册相关页或软件配置截图。

序列号可以只保存在受控证据目录，对外材料中再脱敏。

## 二、原始 H/V 数据

请逐项确认：

1. 能否同时保存 H、V 两通道的原始复数 IQ，而不是只有幅度、功率或 RD 图片；
2. H/V 是同时采样、交替发射/接收，还是软件切换；两通道的时间差和相干关系是什么；
3. 是否保留逐脉冲连续慢时间序列、PRF 和脉冲序号；跨帧/跨文件是否连续；
4. 输出前是否做脉冲积累、检测、门限、降采样、相位校正或其他不可逆处理；
5. IQ 的文件格式、变量名、数组维度、复数类型、量化位数、字节序和缩放系数；
6. 能否提供一份最小原始样例及其对应配置，用来检查时域、极化和微多普勒可用性。

若 H/V 不相干，项目仍可研究双通道功率特征，但不能把相对相位或散射参数作为可信
极化特征；这一点必须由设备证据决定。

## 三、时间与顺序

请说明：

1. 每帧或每个脉冲是否带真实采集时间戳；时间源是什么，精度是多少；
2. 是否有单调硬件序号、扫描号、波束号和时钟重置标记；
3. 采集软件显示时间、文件创建时间和真实硬件采集时间之间是什么关系；
4. 能否导出丢帧、缓存溢出、时钟重置和采集错误日志。

文件名时间和文件系统修改时间不能代替硬件采集时间。

## 四、5 分钟连续写盘实测

在固定配置下连续保存原始 H/V IQ 至少 300 秒，并记录：

| 项目 | 需要填写 |
|---|---|
| 开始/结束 UTC |  |
| 计划时长与实测时长 / s |  |
| 文件数、首末硬件序号 |  |
| H/V 总字节数 |  |
| 原始流速 / MB/s |  |
| 存储实测持续写速 / MB/s |  |
| 写速/流速比值 |  |
| 丢帧、序号跳变、缓存溢出、程序异常 |  |
| 使用的软件、配置和存储设备 |  |

放行线：连续时长不少于 300 秒，写速/原始流速不少于 1.5，且不存在无法解释的序号
中断。不要为了通过测试降低到不能支持正式实验的采集配置。

```text

    CAP_RAW_COMPLEX_HV/
```

原始大文件不进入 Git。仓库只保存小型报告、配置、哈希、受控相对路径和验收结论。

## 六、能力门判定

收到附件后，项目按以下六项审计：

- `CAP_RADAR_ID`
- `CAP_RAW_COMPLEX_HV`
- `CAP_HV_COHERENT`
- `CAP_SCAN_MAPPING`
- `CAP_CONTINUOUS_MIN`
- `CAP_STORAGE_RATE`

六项全部有真实证据并通过，才进入时间同步台架。任何一项未知都保持 `BLOCKED`，不会
用旧数据或聊天描述自动补成 `PASS`。
