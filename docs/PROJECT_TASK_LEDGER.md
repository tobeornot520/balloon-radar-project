## 1. 项目当前方向

项目当前不以“换一个更大的网络”为目标，而以如下问题为主线：

> 在已有 H/V 双极化雷达数据上，如何提高低慢小目标检测的可信度，重点降低复杂背景下的虚警，同时保持目标检测和距离—速度定位能力？

现阶段证据对象主要是 UAV 与背景，因此当前交付物是检测、定位和虚警抑制前端。空飘球
有载/无载、载荷类型和运动状态是后续数据到位后的任务，不能用当前 UAV 结果代替。

推荐技术链：

```text
数据事实核对
  -> Power2 / DPG-FCN 基线
  -> 逐样本虚警与目标失败分析
  -> H/V 极化特征稳定性审计
  -> 物理特征增强或候选 ROI 复核
  -> 轻量、因果、目标保护的背景校准
  -> 独立外层评价
  -> 新空飘球数据上的分层分类
```

## 2. 我们的分工

### 你的任务：研究负责人和物理事实的把关人

你不需要独自编写全部代码，但必须负责不能由代码自动替代的判断：

- 向学长确认 H/V 通道含义、输入是否为复数 IQ、脉压/FFT/归一化处理、PRF、标签定义和
  Tian 复现条件；
- 逐步查看目标、虚警和困难样本，给出能被雷达物理支持的解释，不能把文件名或猜测当
  成地物类别；
- 决定研究问题、主要指标、停止规则和是否进入下一阶段；
- 维护实验记录：每次正式实验都记录数据清单、分组、配置、代码提交、权重哈希、结果和
  决策；
- 在真实设备或新数据可用时，负责协调采集、同步、标定、真值和场景记录；
- 阅读生成的表格和图，确认结论是否符合你的物理理解，并在论文中承担最终解释责任。

### 我的任务：工程实现、审计和结果整理

我负责把已确定的研究问题变成可运行、可追溯、可拒绝的实验：

- 维护数据接口、特征提取、模型、评价、审计和分享包脚本；
- 先做验证集和训练组上的特征稳定性、来源泄漏、困难组压力检查，再决定是否训练；
- 实现预登记的极化特征增强、局部背景校准和目标保护约束，并保留安全基线；
- 统一输出 pooled、macro、最差折、扫描组不确定性、Pd、Pfa、AUC、定位误差和配对变化；
- 对 Tian 复现做条件核对、输入对齐和失败诊断，不把失败迁移包装成成功复现；
- 维护任务台账、实验台账、论文/分享文档、本地 Git 提交和最新两个分享包；
- 在没有数据或设备证据时明确标记 BLOCKED，不用模拟成功填补缺口。

### 共同任务：决策门

任何新方法进入外层测试前，双方共同确认：

1. 数据范围和组隔离已经写清楚；
2. 主要指标和目标保护约束已经预先登记；
3. 结构、损失、阈值和后处理只由训练/验证数据选择；
4. 失败判据和停止条件已经确定；
5. 测试集只评价一次，结果不反向选择方案。

## 4. 分阶段计划与双方验收

### 阶段 A：事实与基线（当前优先级 P0）

你的工作：

- 向学长发出一页问题单，优先获取 D01、D02、D10 所需信息；
- 从当前输出中挑选一小批目标、困难背景和虚警样本，逐张看图并记录“可解释/未知”；
- 阅读一份特征定义表，指出哪些物理解释需要降级为相对量。

我的工作：

- 冻结当前 DPG-FCN、sample-independent BC、scan-aware BC-DPG 和 V2 的名称、证据角色和指标；
- 生成虚警/目标配对分析表，避免重新训练和测试集调参；
- 把学长答复接入数据卡和 Tian 复现条件请求。

阶段验收：数据事实清单、当前模型主表、困难样本表和未决问题清单都存在，并且每个结论
带有数据范围、划分方式和证据等级。

### 阶段 B：极化特征挖掘（P0/P1）

你的工作：

- 先确认 H/V 的物理含义和可否进行相位类运算；
- 对 ratio、差异、总功率、归一化能量和相对相关特征给出物理解释；
- 参与决定主验收是“Pfa 降低且 joint Pd 不下降”还是预登记的容差版本。

我的工作：

- 从原始可用通道计算候选特征，区分 Power2、相对极化特征和未经标定的绝对物理量；
- 按扫描组和背景组审计 AUC、PR-AUC、低 FPR 排序、分布稳定性和来源泄漏；
- 只有验证组稳定后，才做轻量特征融合或 ROI 精修模型。

阶段验收：至少一份特征目录、一份跨组压力报告、一份失败/停止记录；如果特征只编码日期
或来源，停止模型化并保留负结果。

### 阶段 C：小幅方法改进（P1）

你的工作：

- 确认方法是否符合研究故事和硬约束；
- 检查困难样本是否真的改善，而不是只看 pooled 数字；
- 在结果评审会上决定继续、降级或停止。

我的工作：

- 实现最小增量模型：极化特征融合、候选 ROI 精修或目标保护残差，只开放一个变量；
- 采用训练/验证选择，保留 epoch 0 和固定安全基线；
- 报告每折、配对样本变化、目标损失和新增虚警。

阶段验收：困难折通过预登记门槛，且方法复杂度、运行时间和解释性有记录；未通过则不扩展
六折，不用测试结果继续调参。

### 阶段 D：因果与外部数据（P0，但当前阻塞）

你的工作：

- 获取真实采集时间、雷达/视频同步、H/V 标定、事件标签和同条件背景；
- 按合同完成 capability、sync、calibration、dry run、pilot 证据；
- 新数据完成后负责场景和真值审核。

我的工作：

- 把真实顺序接入 causal BC 训练和回放；
- 先在训练/验证选择历史窗口，再对外层锁定集一次性评价；
- 接入连续慢时间 STFT、微多普勒、轨迹和分层分类接口。

阶段验收：causal 与 locked-evaluation 两道门打开；在此之前，所有实时/微多普勒/空飘球

## 5. 明确避雷清单

| 禁止做法 | 为什么危险 | 替代做法 |
|---|---|---|
| 为了涨点盲目换 Transformer、YOLO 或更深 FCN | 没有补充信息，容易把数据泄漏或过拟合误当收益 | 先分析虚警机制和特征稳定性 |
| 只报告 AUC | AUC 不能代表固定阈值下的实际虚警 | 以 Pd、Pfa、worst-fold、joint Pd 和定位误差为主 |
| 用测试结果挑阈值、半宽、联合 AND/OR 或历史窗口 | 把开发结果包装成盲测 | 只用 train/val 选择，外层只评价一次 |
| 把完整扫描上下文称为实时模型 | 可能读取当前样本之后的信息 | 命名为 offline scan-aware upper bound，另训 causal 版本 |
| 把 H/V 相对量称为绝对 ZDR 或物理微多普勒 | 当前标定、PRF、连续慢时间未充分确认 | 使用 relative / ZDR-like，并明确限制 |
| 把 UAV 结果写成空飘球载荷识别 | 类别、平台和标签不一致 | 现阶段写检测定位前端，等待新数据 |
| 直接删除未经核对的历史原始记录 | 破坏决策追溯 | 原始记录本地保留、Git 忽略、分享包脱敏 |
| 重新跑所有已删除的旧训练轮次 | 成本高且不能恢复原实验条件 | 只保存当前冻结证据，新实验严格记账 |
| 复制切片制造“更多独立样本” | 虚增样本量和泛化能力 | 按 session/scan 做独立划分 |
| 在没有设备证据前开放全极化、时序大模型或光学融合 | 数据条件尚不存在 | 先搭接口和门禁，数据到位后再启动 |
