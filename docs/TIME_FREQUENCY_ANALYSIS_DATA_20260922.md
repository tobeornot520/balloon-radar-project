## 3. 说明文档中提供的信息

配套 `docx` 对时频处理的描述是：

- 每个案例的点迹回波 IQ 数据按时序合并为一个完整序列；
- 每个案例使用 16 个点迹脉冲；
- FFT 点数为 128；
- STFT 窗函数长度为 16；
- 文字描述了飞鸟（群）、警用无人机、空飘无动力目标和气球的特征观察。

这些内容是来源说明和处理备注，不等同于已经审计过的数据标签或设备合同。说明文档没有解释：

- `DA40` 与“飞鸟（群）”或 `民航` 的对应关系；
- `.bin` 的二进制编码、数据类型、字节序、字段布局和 IQ 通道排列；
- `.fig` 是否由同一 `.bin` 生成、是否含有额外处理参数；
- 速度轴的物理换算、PRF、载频、采样率和距离/速度单位；
- 每个文件对应的真实 session、场地、天气、目标真值和采集配置。

因此当前不根据说明文档自动生成训练标签，也不把文件名中的数字直接写成物理速度或时间戳。

## 4. 当前数据用途分级

### 可以立即做

1. 检查 `.bin` 和 `.fig` 的一一配对关系；
2. 读取/逆向分析 `.bin` 格式，确认是否为 16 点迹 IQ 序列；
3. 用已知 128 点 FFT、16 点窗复现 STFT 流程；
4. 比较不同来源类别的时频图和统计特征；
5. 建立数据读取接口、可视化和人工复核工具。

### 暂不能直接做

1. 直接并入现有训练集或建立正式分类准确率；
2. 把 `DA40`、`民航`、`空飘` 和 `警用无人机` 当作已确认的互斥物理类别；
3. 把文件名中的数字解释为 m/s、米或 UTC 时间；
4. 声称这是独立外部测试集；
5. 根据 `.fig` 的图形外观反推未经确认的标签或处理参数。

当前最合理的状态是：**新接收的时频接口/探索数据，标签和物理坐标待审计**。

## 5. 与项目现有数据的关系

这批数据可为项目后续时域/时频方向提供接口和候选样本，但不能覆盖当前主线的证据缺口：

- 它不自动提供 H/V 复数通道、极化标定或通道相干证据；
- 它不自动提供连续 session、逐样本硬件序号、丢帧和重启记录；
- 它不自动提供同日期、同场地、同配置的目标/背景对照；
- 它不自动提供空飘球有载/无载、摆动/旋转等状态真值；
- 它不改变项目当前 `4/6 BLOCKED_EXTERNAL` 状态。

在正式训练或论文评价前，应先通过数据格式、标签、物理轴、分组和同步审计。

## 6. 建议的后续审计顺序

1. **文件格式探针**：确认 `.bin` 是否包含固定长度、复数/实数、端序和字段结构；
2. **配对复核**：确认每个 `.fig` 是否由对应 `.bin` 的同一处理过程生成；
3. **来源标签确认**：向数据提供者确认 `DA40`、`民航`、`空飘` 和“警用无人机”的真实语义；
4. **处理参数确认**：确认 16 点迹、128 点 FFT、16 点 STFT 窗是否适用于全部文件；
5. **物理坐标确认**：索取 PRF、采样率、载频、速度/距离换算和单位；
6. **实验元数据补齐**：补充日期、场地、天气、雷达配置、目标状态和真值；
7. **按 session 分组**：禁止把同一连续飞行或同一案例切片后随机跨训练/测试；
8. **先做探索性报告**：只报告文件级统计、时频图和格式审计结果，不报告未经锁定的泛化性能。
